## 5. 10 条可借鉴经验

1. **先定义“可验证的完成”**：目标写成可机械判定的验收条件；验证拆成 flag_capture / effect_proof / poc_crash / oracle 四类，由独立验证引擎裁决，Agent 不能自判（蛙池、度小满、京东）。
2. **执行者与审计者分离**：Auditor 只读复核；Executor 每轮全新上下文；Harness 是唯一状态写入方；Judge 用便宜模型输出结构化 JSON（蛙池、WgpSec、度小满、绿盟）。
3. **证据必须包含业务语义**：仅 HTTP 证据不够；“头像可被他人查看”技术上像越权、业务上设计允许；先分公共/私有接口再 AI 对照（UniSec、Shannon、联想、字节、美团）。
4. **图要完整，渲染视图分层**：图是唯一真相源，压缩只在渲染层；Index ≤3KB / Summary 按需 / Raw 对象存储；hint 全量、失败方向保留、常规 fact 只留最近（木头、京东、度小满、腾讯云）。
5. **价值评分 watchdog，而非固定超时**：300s 基线，按新增 fact、工具成功率、有效信息、高价值突破综合评分；持续上升动态延长，无价值 SOFT_WARN → 缩短 → TERMINATE，终止前回填成果（木头、WgpSec、绿盟）。
6. **确定性代码做调度/提交/审批/状态写入**：LLM 只做语义判断；Decision Router 让 60-80% 决策走规则；LLM 调度会刷简单题、提前停 worker、限流时整体失效（WgpSec、京东、蛙池、度小满、明.Sir）。
7. **工具接口按“LLM 一定会乱传参”设计**：5 层容错（单字段 JSON blob→evidence 反查→description 降级→URL 正则→双 unknown 拒绝）；`vuln_type:endpoint:param` 归一化去重；MCP 健康检查/0-turn 重试/finally 落报告/错峰（WgpSec、UniSec、HexStrike）。
8. **Skill 要场景化、按需加载、可度量**：4000 行 Skill 拆成 FuzzZero/FuzzOne；31% session 零调用说明“有知识≠会用”；字节走 Prompt→Few-shot→RAG→Reranker（木头、奇安信、WgpSec、字节）。
9. **误报治理靠对照实验+业务上下文+允许不确定**：多模型 COT + 原子化任务 + RAG + Workflow；三分法允许“不确定”；状态复位/对照验证/人工确认绕不开（美团、字节、QCon）。
10. **成本按角色分层，用单位有效发现成本衡量**：planner 强/worker 中/judge 便宜；单目标预算熔断；Anthropic 0day 净利约 $200、Shannon 约 $50/1.5h（WgpSec、绿盟、Bytex、Anthropic、Shannon）。

## 8. 总体判断

中文社区已从“给工具接个 LLM”进入 **Harness 工程**阶段，共识五件事：独立验证/审计、上下文分层、确定性优先、三层安全边界、成本分层。与本项目“双图+目标闸门+证据链+三层审批”高度同构；主要差距在**独立 Auditor、价值评分 watchdog、工具参数归一、网络层硬围栏**四点。
