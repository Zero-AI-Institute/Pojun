# AI 渗透 Agent 学术与基准调研（2024-2026）

> 调研日期：2026-11-24。数字均来自原文/官方页面；原文没有的标“未找到/未核实”。

---

## 0. 结论先行

- **主线不是“模型变强”，而是“结构化 agent + 验证”**。纯 ReAct/单 agent 在真实基准上仍很低：CVE-Bench 最高 13%，AutoPenBench 自主 21%，PentestEval 全自主 3%-6%。
- **脚手架与模型同等重要**。同一个 GPT-4o 在 CVE-Bench 不同 scaffold 下可从约 2.5% 到 13%；同一个 Opus 4.5 下 PentestGPT v2 在 XBOW-104 上 91%，PentestAgent 61%。
- **长程任务第一瓶颈是状态/难度管理，不是工具数量**。PentestGPT v2 的难度评估把 Type B 失败从 58% 降到 27%；外置 memory 再 +8 点。
- **论文数字不可直接横向比较**：pass@1 vs pass@5/@30、自主 vs 人助、CTF vs 真实 CVE、最佳-of-N、基准污染，都会造成数倍差异。
- **生产侧已有真实成果，但都依赖确定性验证/人工复核**：XBOW 约 1,060 条 HackerOne 提交、130 条已修复；AIxCC 找到 54/63 个注入漏洞；Big Sleep 发现 SQLite 真实漏洞；Aardvark 报告 10 个 CVE。

## 4. 架构拆解

| 系统 | 编排 | 结构 | 状态/记忆 | 验证 | 工具 | HITL |
|---|---|---|---|---|---|---|
| PentestGPT | 三模块串行 | 单 LLM+人执行 | 文本 PTT | Reasoning，无独立验证 | CLI，禁自动扫描器 | 强 |
| PentestGPT v2 | EGATS 攻击树搜索 | 单编排+工具/技能层 | 外置 memory + 树 | TDA 难度+证据置信度 | 38 typed tools | 可切换 |
| AutoPT | 有限状态机 | 单 agent 多状态 | 会话状态 | Rule state check | Terminal/Playwright/Search | 无 |
| VulnBot | PTG DAG | 5 模块多角色 | 向量 RAG+PTG | Check/Reflection | Nmap/Dirb/Nikto/WPScan/MSF/Hydra | 三模式 |
| RapidPen | 分层 ReAct | 18 LLM 实例 | PTT+RAG | Log Analysis 自校正 | MSF/nmap/rustscan | 无 |
| AutoPentester | 迭代循环 | 5 agents | RAG+历史 | Verifier+Repetition Identifier | CLI | 交互 |
| XBOW | 任务流水线 | agents+validators | trace | 确定性 validator | 自研 | 提交前人工 |
| EnIGMA | 单 agent 循环 | 单 agent | Summarizer | 无独立验证 | ACI/IAT | 无 |

**Planner 三形态**：文本任务树（简单但易写坏）→ 有限状态机（可控但领域特定）→ 外置攻击树/任务图（2026 最明确增量）。结论：planner 不应“让模型在对话里记住计划”，而应“外部数据结构 + 模型只做局部决策”。

**单 vs 多 Agent**：层级式有效（HPTSA planner+task agents+manager，pass@1 4.3×，42%@5 vs 18%@1；去掉层级 pass@1 低 13×）；“多 agent”本身不是增益（VulnBot 30.3%、PentestEval 6%/3%）。角色专精+层级+共享状态才有稳定收益。

**Memory/Context**：向量 RAG（VulnBot/RapidPen/AutoAttacker）；摘要/状态压缩（EnIGMA +2.5；HackingBuddyGPT 33%→66%，128k 与 8k 均 66%）；外置 memory（PentestGPT v2 +8）；上下文负载 60% 时准确率 94%→78%，80% 时 61%，40% 是理想窗口。

**Reflection vs 验证**：Reflection 对状态理解有效（33%→66%；去 Reasoning 只剩 53.6%），但不能替代验证（XBOW 用确定性 validator；CVE-Bench v2 修复评分漏洞后 -32.5%）。PentestGPT v2 证据置信度：verified 1.0 / confirmed 0.8 / plausible 0.5 / speculative 0.3。

**Tool/Skill**：typed interface + RAG 命令生成主流；工具层收益有上限（PentestGPT v2 Tool +14 XBOW，但 +1 13 台、0 GOAD）；工具层解决能力型失败（Type A），不解决规划型失败（Type B）。

**HITL**：AutoPenBench 21%→64%；AutoPentester 人工交互 1.13 vs 15.36 但更慢更贵；HITL 不是免费正确性。

**Long-horizon**：GOAD 4/5；AISI 32 步 3/10；Cybench 无模型解出 >11min FST；CyberGym PoC>100B 约 10%；PentestGPT hard 0/2；AutoPT complex 20%。长程不是“多跑几步”，而是“正确分支坚持、错误分支早停”。

## 5. 评测与可比性

指标：success/task completion、subtask completion、coverage、cost、wall-clock、FP/FDR、evidence quality、pass@1/pass@k。必须分开报告。

数据集：AutoPenBench、Cybench、NYU CTF、PentestGPT Benchmark、XBOW-104（已过时）、CVE-Bench、CyberGym、VulHub/HTB/VulnHub/GOAD、真实 SRC。

**不可比示例**：PentestAgent 67 VulHub 74.2% vs PentestEval 3%；PentestGPT 13 targets 61.5% vs PentestEval 31%；Cybench 最佳 17.5% vs XBOW-104 85%；CAI 汇总 11× 快 vs hard/insane 0.91×/0.65×。

**六个变量**：模型、重试/预算、人类参与、任务选择、判定方式、基准时效/污染。

## 6. 什么真的有用

**有数字支撑**：
1. 层级规划+任务分解：HPTSA 4.3×；AutoPT 41% vs 22%；PentestGPT v2 91% vs 61%。
2. 外置攻击树/状态机：54→68→77→85；PSM +19；PTG 子任务 49.05%→69.05%。
3. 难度评估/剪枝：TDA Type B 58%→27%；TDA-EGATS +9。
4. 状态/反思/摘要：33%→66%；Summarizer +2.5；去 Reasoning 只剩 53.6%；memory +8。
5. 工具/技能层：Tool +14（XBOW）；不完整命令 4.46→0.13；IAT +2.5；但长程收益迅速衰减。
6. 确定性验证：XBOW 85%；CVE-Bench v2 -32.5%；AIxCC accuracy multiplier；IRIS FDR 90.03→84.82（人工抽检 46%）。
7. 测试时扩展/重试：87% pass@5 vs 40% pass@1；28.9%@1 vs 66.7%@30（约 $45/task）；13% 是 success@5。
8. 人助：21%→64%，目前最稳定提升手段。

**被高估**：
- “多 agent”本身（无层级/共享状态可能不如单 agent）
- PentestGPT Generation 模块（主要提升操作精度）
- “大上下文”（8k 与 128k 均 66%）
- RAG/经验复用（同漏洞泄漏 vs 可迁移经验）
- 基准 SOTA（XBOW-104 过时；Cybench 2024 模型）
- “全自主”（高分多为最佳-of-N/人助/预配置靶场）
- 工具数量（38 工具 XBOW +14，但 13 台 +1、GOAD 0）
- 成本叙事（CAI 156× 便宜但 hard/insane 更慢；AutoPT $0.0099 是预配置 VulHub）

## 7. 失败模式

幻觉/自评成功、工具误用/命令不完整、重复劳动/死循环、上下文丢失、误报、范围/越权、难度长尾、基准污染/泄漏。

## 8. 12 条工程结论

1. 评测必须固定 scaffold/模型/预算/重试，否则数字没意义。
2. 分层规划/攻击树/状态机是最稳结构性增益。
3. “多 agent”本身不是增益；角色专精+层级+共享状态才是。
4. 上下文/状态管理是长程第一瓶颈。
5. 难度感知与剪枝是 2026 关键增量；工具堆叠会饱和。
6. 工具层解决能力型失败，不解决规划型失败。
7. 自主 vs 人助差距大；全自主在真实/复杂基准仍低。
8. 必须同时报告 pass@1/pass@k；重试有效但成本线性。
9. 成功判定必须确定性验证/环境状态；LLM 自评和宽松评分会造假。
10. RAG 有收益，但要分离同漏洞泄漏与可迁移经验。
11. “便宜”不等于总成本低；时间/人工/验证/误报都要计。
12. 真实漏洞发现集中在白盒/有描述/可验证场景；开放未知漏洞仍是前沿。

## 9. 对本项目的 5 条建议

1. **Planner 做成“攻击树 + 预算/难度调度器”**，不要聊天式 ReAct：`AttackNode{Type,StateRef,EvidenceRefs,Promise,TDI,Budget,Attempts}`，树/图外置，LLM 只做局部决策；BFS 侦察→DFS 利用，失败 3 次剪枝，新凭据重评估；planner 模型无关，用两个 frontier 模型回归。
2. **EvidenceStore 与 ContextProjector 分离**：所有工具输出/HTTP/截图/hash/置信度 append-only 内容寻址；Planner/Worker 只拿 `Project(ctx,task)` 的“相关证据+摘要+未验证假设”；ContextBudget 按模型窗口/任务配置，超阈值强制 summarize/prune。
3. **技能 typed contract + 确定性 Validator**：输入/输出 schema、前后置条件、超时、沙箱、幂等、允许命令/域名/路径、解析器、版本；XSS headless 验证、SQLi 真读列、SSRF 只允许目标发起、文件读取拿指定内容、RCE 回连；Finding 必须绑定 EvidenceBundle 才进报告。
4. **多基准、分口径、防泄漏/防奖励黑客的评测**：AutoPenBench/Cybench/CVE-Bench/CyberGym 子集/XBOW-104（注明过时）+ 自家靶场；同时报 pass@1/pass@k/cost/wall-clock/FP/FDR/evidence；固定模型/预算/重试/快照；RAG 按 CVE 去重，禁止同目标成功 PTT；评分器只读环境状态。
5. **先 HITL/范围控制，再谈全自主**：ToolExecutor 最外层强制 Scope（域名/IP/端口/路径/时间窗/禁止动作）+ ApprovalPolicy；高风险动作人工批准；kill switch + AuditEvent；报告从证据链自动生成，无 validator 的 finding 只进“待验证”。
