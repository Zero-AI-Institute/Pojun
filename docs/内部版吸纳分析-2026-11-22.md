# 内部版吸纳分析（2026-11-22）

> 对象：内部版 v0.9.34 → v0.9.67（33 个版本，2026-11-15 → 11-22）。
> 基线：Pojun v0.4.95。已同步等价项单独标注，避免重复建设。
> 结论先行：**内部版最大的增量是「后渗透引擎」一个完整能力域**（v0.9.47/57/58/59/61/65/66 七个版本迭代），
> 其次是「opsec 请求治理 governor」与「验证优先工具包」。散件修复类可直接同步。

## 一、逐块对比与吸纳判定

### ① 后渗透引擎（v0.9.47/57/58/59/61/65/66 —— 最大增量，L 级）

内部版七轮迭代出的完整能力域：
- **postex_states 状态机**：每任务每主机 detect/foothold/verify/enumerate/privesc/persist/cleanup/done 八阶段；
  autopilot 任务 30s 巡检自动派阶段意图（priority 80）；每阶段最多 2 次，失败置 blocked 不无限重试。
- **统一访问会话**：`access_sessions` 把 WebShell/反弹 shell/SSH/WinRM/C2 agent 统一建模；
  `access_register/probe/exec/upload/download` 全套。
- **WebShell 工具**：`webshell_deploy`（multipart/原样写+回读验证）、`webshell_exec`（任务隔离）；
  v0.9.66 修复 HTTPS 自签证书（InsecureClient 走录制代理跳校验）。
- **权限维持**：`persistence_plan/install/verify`（cron/systemd/SSH keys/Windows 计划任务/服务/注册表 Run）；
  v0.9.48 修 Windows cmd 双引号转义；任务结束自动 cleanup。
- **横向编排**：`lateral_discover/plan/move`（SSH 密码/私钥 + WinRM 原生 NTLM，只做凭据登录不投放）；
  每目标 2 次失败跳过；`auto_lateral` 默认 autopilot 开、单任务 5 台深度 1。
- **统一隧道**：`access_tunnel_start/stop/list`——SSH 原生 SOCKS/转发、chisel 反向 SOCKS（随机认证+随机
  文件名+结束清理）、AdaptixC2 连接器纳管（独立 HTTP 客户端无 GPL 代码）；`http_request` 支持
  `tunnel_id` 走已建立隧道。
- **收口教训（65/66 两轮审计）**：blocked/failed 终态化防重复派发（实测提权意图重派 17 次）、
  阶段切换重置 attempts、意图按阶段隔离、离线≠失败、平台自身主机排除（含 169.254 排除 APIPA）、
  手动阻断按钮、RCE findings 分支尊重终态、派发前重读状态。
- **opsec_profile 联动**：quiet 不自动植入/提权/维持/横向；balanced 提权横向但不自动维持；aggressive 全开。

**判定：建议吸纳，但按 Pojun 的授权口径裁剪**——Pojun 面向 SRC/授权客户，`auto_postex/auto_persist`
默认应关（手动任务只积累状态），quiet/balanced 档语义保留；WebShell/持久化工具挂 guard 审查链 +
任务授权边界。工作量 L（状态机+会话模型+四类工具+横向+隧道），建议拆两批：先「访问会话+WebShell+
持久化记录」（M），再「自主推进+横向+隧道」（L）。

### ② opsec 请求治理 governor（v0.9.61 —— M 级，与方向调研 OPSEC P0 高度重合）

- 任务级 `opsec_profile`（quiet/balanced/aggressive）控制速率/并发/抖动/预算/熔断/下载上限；
- 新 `opsec` 包统一包裹原生 HTTP：令牌桶+并发信号量+抖动+预算+429/5xx 熔断+WAF 降速，
  计数持久化 settings，`opsec_status` 工具+planner 熔断告警；
- guard 自动给 nuclei/ffuf/katana/arjun/sqlmap/nmap/gobuster/feroxbuster/dalfox 补限速参数
  （手写超限夹逼、低延迟抬升、aggressive 不改写）；
- **感知一致性**：同任务固定浏览器画像（UA/Accept-Language/Sec-CH-UA），全工具一致，不每请求随机。

**判定：强烈建议吸纳**——这就是我们方向调研 OPSEC P0 里「扫描器参数守门」+「感知一致性」的
已验证实现，等于 P0 批次可以直接对齐内部版接口。缺的仍是我们独有的 uTLS（内部版也明确列为
已知限制）。工作量 M。

### ③ 验证优先工具包（v0.9.61 —— S-M 级）

`authz_matrix`（匿名/多会话矩阵）、`validate_oob`（listener 回连 token）、`jwt_probe`
（alg=none/弱密钥/kid/claim 篡改）、`cors_probe`、`graphql_probe`（内省/批量/别名）、
`upload_probe`（benign marker/双扩展/回读验证）。
全部 governor 限速、先基线后变体、输出 `confirmed/likely/inconclusive` 不自动 report、
证据落 runDir 0600。
另有 `discovery_plan`（按档位组 katana/ffuf/arjun 命令）/`discovery_ingest`（解析 JSONL 登记
endpoint）/`coverage_status`（10 类漏洞×资产矩阵缺口提醒）。

**判定：建议吸纳**——与我们 validators（RCE/XSS/SSRF 机械断言）互补：他们宽（每类一个探针工具），
我们深（机械 verdict+标记闭环）。合并后验证工具面完整覆盖 OWASP 常见类。工作量 S-M。

### ④ 专家体系（v0.9.35-43/55 —— M 级，产品形态差异）

6 个内置专家（verifier 证据审查/recon 侦察扩展/exploit 利用链/remediation 修复建议/
reporter 报告/retester 复测）、专家工具白名单与权限矩阵（只读/可执行开关）、会话分组折叠、
内联回放。Pojun 无此形态（chat 有对话但没有任务绑定的专家角色）。

**判定：价值真实但与 Pojun 单管理员形态有摩擦**——专家本质是「绑定任务上下文的专职
agent 会话」。建议 v0.4.96+ 单独评估，先吸纳「verifier 只读专家」这一个（与 evidence_check/
独立复现规则联动），验证形态再扩。工作量 M。

### ⑥ 预设参数预填的差量（v0.9.64 —— S 级，补 v0.4.93 缺口）

我们 v0.4.93 已做 session_header_key/user_agent/max_tokens_field；内部版多出：
- **`max_tokens` 预填**：Anthropic 协议预设全部预填输出上限（Anthropic 必填，缺=400）；
  OpenCode Go 预填 8192；
- **模型级参数覆盖**：ModelEntry 支持同名字段（gpt-5.2 → max_completion_tokens，
  gpt-4.1 → max_tokens，切换模型自动校正）；
- **thinking_type/reasoning_effort 预填**：GLM 预填 thinking.type=enabled；
- **客户端 UA**：OpenCode Go 预填 `coding-agent/1.0`。

**判定：全部吸纳**（S 级，一次补齐）。

### ⑦ 明确不采纳

- **v0.9.52 删除授权话术/judge 目标侧一律放行**：内部版面向红队作业的合规取向变化，
  与 Pojun 的 SRC/客户委托授权口径相反——保持我们的授权边界与守卫体系不动。
- 后渗透的默认自动化激进档（auto_postex/auto_persist 默认 true）：Pojun 面向 SRC，
  默认全部关、手动任务只积累状态。
- UI 抽屉细节批次（44/45/46）：按需逐个看。
