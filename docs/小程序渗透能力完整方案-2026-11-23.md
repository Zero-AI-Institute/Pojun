# 破军 · 微信小程序渗透能力完整方案（2026-11-23）

> 目标：把「上传小程序包 → agent 自动解包 → 静态审计 → 动态验证 → 证据 → 报告」做成平台原生能力。
> 设计原则：**正常渗透流程不变**；用户把 wxapkg / 包含包的 zip 作为附件上传，并在任务里说明"这是微信小程序，做渗透测试"，对应 skill 与 Playbook 自动加载。
> Skill 内容只写纯方法论与技术操作，不写授权/约束段落（约束由模型侧统一处理）。

---

## 0. 结论与范围

- 平台侧改动集中在 4 个核心：**一个技能目录 + 一条可见性绑定 + 一个目录型扫描工具 + 一个 Playbook 批次**；上传通道、技能注入、证据/报告链路全部复用。
- 包处理采用**质量优先的多工具阶梯**：wedecode（4.x/分包，GPL，外部进程）→ unveilr（WXML 质量交叉验证，GPL，外部进程）→ KillWxapkg（MIT，沙箱内快速兜底）；**自研 Python 安全解包器**负责解密、索引预校验与安全提取（防路径穿越），不依赖外部工具的退出码。
- 静态审计：新增工具 `miniapp_audit`，**复用 js_audit 内嵌 Python 脚本**，只加 `--dir` 分支（不改 js_audit 的工具 schema，绕开老库 required 迁移坑）。
- 动态验证：复用平台既有 `session_login` / `http_request` / `diff_responses` / `traffic_*` / 代理录制；PC 微信抓包由用户在 OS 层配代理，skill 给完整操作步骤。
- v1 不做：手机端自动拉包、wxapkg 重打包/Hook、自研完整解包器、支付宝/抖音等其它平台、纯 LLM 静态报告。
- 交付批次：v0.4.99 P0 单批做完；P1/P2 见 §10。

### 2.5 脚本要点

`miniapp_unpack.sh`（编排器，不用 `set -e` 误判外部工具）：
- 参数：`--in <路径>`（必填，文件/目录/zip）、`--out <根>`（默认任务根 `miniapp/`）、`--appid <wx...>`、`--quality auto|wedecode|unveilr|fast`。
- zip 输入：`unzip -o` 到临时目录再找 `*.wxapkg`；拒绝 `..`/绝对路径条目；限条目数/总量。
- 包收集：按 `appid+version` 分组；优先 `__APP__` + 同版本全部分包；插件包单独处理；计算每个包 SHA-256。
- **AppID 提取**：`--appid` → 路径段 `wx[0-9a-f]{16}` → 文件名 → 版本目录名；**永远不要把 `wxid_...` 当 AppID**。
- **头部检测**：`plain(0xBE/0xED)` / `V1MMWX` / `mac-legacy(尾部 tag)` / `unknown`。
- **索引预校验（自研 `wxapkg_safe.py`）**：校验魔数、索引长度变体（`14+` 或 `18+`）、offset 基准、文件数/单文件/总量；**拒绝 `..`、绝对路径、盘符、UNC、NUL、超长名、大小写冲突、符号链接**；不通过直接终止。
- **解密**：`wxapkg_safe.py --decrypt`（V1MMWX）→ 明文包；解密后再跑一次索引校验。
- **安全提取**：`wxapkg_safe.py --extract` 到 `raw/`（不执行包内代码），保证即使所有反编译器失败，JS/JSON 也可审计。
- **质量解包阶梯**：
  1. `wedecode`（若安装）：`wedecode <versionDir> --out <src> --clear`；
  2. `unveilr`（若安装）：`node <unveilr>/dist/index.js wx <versionDir> -o <src2> --no-clear-save --no-clear-parsed`；
  3. `killwxapkg`（内置）：`killwxapkg -id <appid> -in <versionDir> -out <src3> -restore -pretty -noClean`，**必须传 `-id`、必须传版本目录（不递归）、必须在沙箱/专用目录运行**。
- **质量门禁 `quality_gate.py`**：`app.json/app-config.json` 可解析、`pages` 非空、`entryPagePath` 合法；每页至少一个非空 `.wxml/.js`；WXML 非空率与占位符比例（`Generated by @unveilr`、空 `<block wx:if>`）；`node --check`/Babel 解析 JS；分包/组件完整性；检测 `batchAddCompiledTemplate`/`__wxCodeSpace__` → 标记 `partial`。选质量分最高的产物作为 `source/`，其余保留供对照。
- **产物校验（不信任退出码）**：KillWxapkg 失败也 exit 0；必须校验首字节、`app.json`、文件数、WXML 非空率。
- 输出：`manifest.json`（appid/version/包哈希/工具版本/status/warnings/wxml_nonempty_ratio）+ 控制台摘要（`APPID=... FILES=... ROUTES=... CLOUD_ENV=... SECRET_HITS=...`）。
- 安全：所有路径 `realpath` 校验在 `--out` 内；解包容器无网络/非 root/资源限制；不 source 包内任何文件。

`wxapkg_safe.py`（纯 Python，无第三方依赖或仅 cryptography）：
- **解密**：读头 `V1MMWX`；已解密（首字节 0xBE、末字节 0xED）直接复制；key=PBKDF2-HMAC-SHA1(appid,"saltiest",1000,32)；前 1024B AES-256-CBC（IV `"the iv: 16 bytes"`）取前 1023B；其余 XOR `appid[-2]`；写 `<out>/<appid>/raw/__APP__.wxapkg`。
- **解析/提取**：大端头；兼容 `indexLen` 含/不含 fileCount、offset 绝对/相对；按 offset/size 读取（允许数据区重叠）；文件名 UTF-8；安全清洗；输出 `name_map.json`。
- **校验**：返回结构化错误码（bad_magic/bad_index/bad_length/unsafe_name/too_many/too_large），供脚本与测试断言。
- 单测：固定 appid + 合成明文验证解密往返；构造 `../evil.txt`、绝对路径、超长名、索引变体、重叠数据区五类 fixture。

## 3. 工具链

### 3.1 工具阶梯（质量优先 + 安全基线）

深度实测结论：**KillWxapkg 不适合作为唯一主解包器**——WXML 丢 `{{}}`/`wx:if`/`wx:for` 绑定（安全审计会漏逻辑）、失败仍 exit 0、包内 `../` 文件名可写出输出目录。因此改为三层：

#### 3.1.1 安全基线：自研 `wxapkg_safe.py`（MIT/自有，必选）

| 项 | 结论 |
|---|---|
| 职责 | 头部检测、V1MMWX 解密、索引预校验、安全提取、结构化错误码 |
| 价值 | 不依赖 Go/Node；防路径穿越；即使所有反编译器失败，JS/JSON 仍可审计 |
| 实测依据 | V1MMWX 算法往返已通过；格式变体（indexLen 含/不含 fileCount、offset 绝对/相对、数据区重叠）已明确 |
| 分发 | 随 skill 脚本，零依赖（cryptography 可用系统包；无则用纯 Python AES 实现或调用 openssl） |

#### 3.1.2 质量解包：wedecode + unveilr（GPL，外部进程，可选安装）

| 工具 | 版本 | 许可证 | 角色 | 关键事实 |
|---|---|---|---|---|
| **wedecode** | 0.10.6 | GPL-3.0-or-later | **主解包**（4.x/分包） | npm 可装；实测 81 文件、WXML 保留绑定；支持 4.x（Issue #53）；坑：重复组件目录、`plugins:{}`、分包页 JS 可能占位、vm2 需沙箱 |
| **unveilr** | 2.0.2（AnkioTomas 镜像 fork） | GPL-3.0 | **WXML 质量交叉验证** | 原仓库 404、npm 下架；需源码构建；AST 还原质量最好；`-f` 可能折断 WXML；删 `plugins`；vm2 critical |
| 许可证处理 | — | — | **只作为独立进程/容器调用，不链接、不改造、不随闭源二进制分发**；安装脚本从上游拉取；镜像/发行版附 license 与源码地址 | |

#### 3.1.3 快速兜底：KillWxapkg（MIT，内置二进制，沙箱）

| 项 | 结论 |
|---|---|
| 仓库 | github.com/Ackites/KillWxapkg v2.4.1 |
| 许可证 | MIT（可集成/可再分发，随包附 LICENSE） |

### 3.2 静态扫描：miniapp_audit（新工具）

**为什么新工具而不是改 js_audit**：js_audit 的 `urls` 是 required，老库 `MergeToolSchemaProperty` 只增不减（`server/assembly.go:369-377`），改 required 需要 bump refreshBuiltin，风险高。新工具=新 DB 行，schema 天然正确。

**复用方式（关键）**：
- 不复制 Python 代码。给现有内嵌脚本加 `--dir` 分支（js_audit 工具永远不传，行为不变）。
- `miniapp_audit` 工具把同一份脚本写到 `runDir/js_audit.py`，调用 `python3 js_audit.py --dir <dir> --out <out> [--appid ...] [--no-osv]`。
- 这样 secret_scan/endpoint_scan/write_sources/osv_check 全部原样复用，维护一份。

**新增 `--dir` 扫描内容**（在内嵌 Python 中）：
1. walk 源目录，按扩展名（.js/.json/.wxml/.wxss/.wxs/.html/.ts/.map）处理；跳过二进制与 >2MB 单文件。
2. `secret_scan` 扩展到小程序专项：
   - AppSecret：32 位 hex，前后文含 `appsecret|secret|app_secret`
   - 云开发 envId：`env\s*[:=]\s*["']([a-zA-Z0-9-]{6,})`
   - 腾讯地图 key：`[A-Z0-9]{3,}-[A-Z0-9]{3,}-[A-Z0-9]{3,}-[A-Z0-9]{3,}-[A-Z0-9]{3,}-[A-Z0-9]{3,}` 且附近 `map.qq.com|apis.map`
   - 高德 key：32 位 hex 且附近 `amap`
   - Bugly/MTA AppID、JWT、PEM 私钥、OSS AK/SK、AES key/iv
   - 熵检测（Shannon ≥ 4.0 且长度≥20）作为候选，标注 `entropy_candidate`
3. `endpoint_scan` 扩展：
   - `wx.request/uploadFile/downloadFile/connectSocket` 的 `url`
   - `wx.cloud.callFunction` 的 `name`
   - `wx.cloud.database().collection("...")`
   - `web-view src="..."`
   - `https?://` 全量域名
4. 云开发汇总：envId、函数名、集合名、存储路径去重。
5. 签名候选：`sign|signature|hmac|md5|sha1|sha256|encrypt|decrypt` 定义与调用点，标注文件:行。
6. 路由：解析 `app-config.json` / `app.json` 的 `pages`/`subPackages`/`plugins`。
7. sourcemap：复用现有 `.map` 还原逻辑（对目录内 `*.js.map`）。
8. OSV：复用 `osv_check`（package.json）。
9. 输出：
   - `report.json`：`{appid, files, routes, endpoints[], secrets[], cloud{}, sign_candidates[], sourcemaps, osv, summary}`
   - `endpoints.txt`：每行 `METHOD? URL  # file:line`
   - `secrets.txt`：脱敏（保留前 4 后 4，中间 `*`）+ `file:line` + 类型 + 上下文
   - 控制台摘要一行，便于 agent 快速决策。

**工具 schema**：
```
dir: string (required)   # 相对 runDir 或任务内绝对路径
appid: string (optional)
osv: boolean (default true)
```
输出目录固定 `runDir/miniapp-audit/`，返回 `run_with_bash`（与 js_audit 一致）。

**注册**：
- `agent/tools_miniapp.go` 新增工具实现；
- 进 `WorkerTools()`（`agent/tools_insert.go:710-760` 区）与 `BuiltinToolSeeds()`（`agent/toolcatalog.go:81-125`）；

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 宿主无 Go / 官方无 Linux 包 | release 预编译 amd64+arm64 + Docker builder + install.sh 下载；自研 Python 安全解包器兜底 |
| **KillWxapkg 包内路径穿越** | 解包前由 `wxapkg_safe.py` 校验索引文件名（拒绝 `..`/绝对路径/盘符/UNC/NUL/超长）；解包在专用目录/容器；产物 realpath 校验 |
| **KillWxapkg 失败 exit 0** | 永不信任退出码；校验首字节、`app.json`、文件数、WXML 非空率 |
| **KillWxapkg WXML 丢绑定** | 质量模式优先 wedecode/unveilr；KillWxapkg 仅 fast 兜底；报告中标注还原工具与质量分 |
| wedecode/unveilr GPL + vm2 | 独立进程/容器调用，不链接；附 license/源码地址；vm2 在无网络沙箱运行 |
| 4.x 路径/分包按需下载 | 递归扫两处 radium 路径；提示用户遍历页面触发分包；前缀 `radium` 路径写进 references |

| Docker 无 hostd 一键安装不可用 | Dockerfile 构建阶段内置 killwxapkg |
| js_audit required 迁移坑 | 不改 js_audit，新增 miniapp_audit + Python `--dir` |
| Playbook v1 flag 老库永久跳过 | 新批次 `task_playbooks_v2` + 独立 seed + 测试同步 |
| save_evidence 拒绝 `..` | P0 放宽为任务根内相对路径校验（已有真实路径包含校验） |
| 上传包被拍平/无目录上传 | v1 用单文件/zip；zip 由技能脚本解压；P1 再做后端目录上传 |
| staging 不迁移/不清理 | 任务描述用绝对路径；P1 建任务时迁移 staging 到 task，加 GC |
| 品牌词泄漏 | 技能文案/脚本避免真实客户名；沿用现有测试 |
