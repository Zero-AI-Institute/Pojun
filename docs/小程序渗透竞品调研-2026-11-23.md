# 小程序渗透竞品与行业最佳实践调研（2026-11-23）

> 纯技术/产品调研。用于确定「行业最好」的能力矩阵与优先级。不含合规约束章节。

---

## 0. 结论先行

1. 商业市场已是全栈竞争，但自动化只到"扫描"，深度渗透仍靠人。腾讯 WeTest 覆盖扫描/渗透/加固/隐私/资产/监控；腾讯云 MPSS 做到仅 AppID 出基础诊断；爱加密 70+ 项自动检测 + JS VMP 加固；知道创宇有明确小程序渗透服务。但"可复现证据 + 越权/支付/云函数动态验证"仍主要是人工交付。
2. 开源解包成熟，端到端产品空白。KillWxapkg（6058★，MIT）解决解密/解包/还原；wedecode（3426★，GPL-3.0）还原质量更全；MPScan（310★，MIT）做到 Windows GUI 一体化静态审计。没有项目把"解包→证据→动态验证→可交付报告→复测"串成平台。
3. AI 小程序 skill 已有先例但早期。`wxmini-security-audit`（425★，7 Agent，无许可证，纯静态）最直接；`miniapp-audit-skills`（MIT，6 skill，动态+静态+证据纪律）最可复用；`wx-mp-mcp`（311★，Apache-2.0）解决"解包+抓包+AI 还原签名"。没有成熟 AI 小程序渗透产品。
4. 众测对小程序漏洞"影响为王"：TSRC 只收影响框架的高危；BILISRC 不收第三方供应商小程序；360SRC 把"App 反编译风险"列为忽略；普通越权通常中危，大量敏感数据/核心系统越权才高危。仅"能反编译/没加固"基本驳回。
5. 行业事实标准三套检测项基线：微信官方接口漏洞扫描 50 项、腾讯 WeTest 小程序渗透 65 项、爱加密 70+ 项。
6. 破军空位不是"再做一个扫描器"，而是"可证明的小程序渗透 Agent"：已有 Agent 编排、Playbook、session_login 双身份、http_request/diff_responses、流量证据、finding 证据版本化与复测、docx 报告；缺包处理、场景化 skill、小程序登录态/抓包/云开发/隐私专项、AST/污点与语义凭据。
7. 许可证注意：wedecode/unveilr 为 GPL-3.0、wux1an/wxapkg 无许可证、wxmini-security-audit/WxLocated 无许可证、DeepAudit AGPL-3.0——代码级集成只能选 MIT/Apache-2.0。

## 1. 商业竞品能力对比

|---|---|---|---|---|---|---|
| 腾讯 WeTest 小程序安全 | SaaS/私有化/CLI | 未公开；入口 AppID/二维码 | 自动静态 + 半自动动态 | 人工渗透，10000+ 用例，65 项 | 加固 5 级、隐私、资产排查、监控、网关 | 扫描自动，渗透人工 |
| 腾讯云 MPSS | SaaS/私有化/API | 未公开；基础诊断仅 AppID | 8 大类基础诊断；前端+后台 Web 扫描 | 深度=线下人工 | 隐私、加固、扫描、盗版监控 | 基础自动，深度人工 |
| 爱加密 | SaaS/私有化 | 未公开 | 70+ 项，静态+动态，代码级定位 | 检测为主 | 加固（控制流平坦化/JS VMP/反调试/一次一密）、隐私 | 全自动+批量 |
| 梆梆 | SaaS/工具 | 未公开 | H5/小程序加固 | 无小程序渗透 | 加固 | 加固自动 |
| 360 | 人工+平台 | 人工 | 工具扫描 | 渗透覆盖微信小程序/公众号；破阵子 AI 通用 | 通用 Web/客户端 | 人工+工具+AI |
| 知道创宇 | 人工 | 人工 | 工具扫描 | SQLi/越权/上传/CSRF/信息泄露 | 通用 Web/APP/小程序 | 人工+工具 |
| 长亭 | 人工+平台 | 未找到 | 慧鉴 SAST | 通用渗透/无锋 | 未找到小程序专项 | 平台+人工 |
| 奇安信 | 人工+平台 | 未找到 | 代码卫士 | APP 安全测试（未列小程序） | 未找到小程序专项 | 工具+人工 |
| 网易易盾 | SaaS | 未公开 | H5/小程序加固 | 无小程序渗透 | 加固+业务安全 | 加固自动 |
| 复旦鉴微 | 学术平台 | AppID+身份信息 | OWASP Top10+小程序特有+60+密钥类型 | 静态为主 | CPRF/跨页面请求伪造/身份混淆 | 研究原型 |

**报告字段**：
- WeTest 渗透：风险点、漏洞类型、评级、检测依据、修复建议；一对一解读+回归复测。
- WeTest 隐私：基本信息、总体结论、检测项结论、明细（风险情形/等级/依据/详情/存证/修复）；覆盖 13 个政策法规/平台规范。
- MPSS 基础诊断 8 类：代码保护、开发测试信息泄露、编码规范、配置风险、账号安全、用户信息安全、内部信息泄露、其他。
- 爱加密：威胁描述、风险详情（代码定位）、修复建议；支持批量。
- 微信官方接口扫描 50 项：风险等级、类型、描述、修复建议；提审必过项。

**自动化边界（推断，有公开依据）**：
- 真正"仅 AppID"可行前提是平台方能拿到包（腾讯作为平台方可以）。
- AppID-only 覆盖：公开面 + 平台侧包分析 + 黑盒接口扫描。
- 覆盖不了：登录后业务逻辑/越权、支付金额/回调/优惠券/退款、云开发环境/云函数/DB/存储规则、多身份对照/签名重算/WebSocket、可复现证据与复测。
- "AppID 出报告"是入口级筛查，不是完整渗透。

## 2. 众测收录与定级（报告设计输入）

| 平台 | 小程序口径 | 定级/关键规则 | 常见驳回 |
|---|---|---|---|
| TSRC | 微信业务范围小程序只收影响框架的高危 | 核心功能高危 4 倍激励 | 业务小程序自身漏洞不在范围；超量取数/SQLMap/DoS 违规 |
| 360SRC | 通用 Web/移动标准适用于小程序接口 | 核心敏感数据泄露=高危；普通越权=中危；"App 反编译风险"=忽略 | 仅反编译无敏感信息、无实际危害 |
| BILISRC | 第三方供应商小程序不收 | 普通越权=中危；大量敏感数据=高危 | 无证据猜测、无法影响他人、第三方小程序 |
| 猎聘 SRC | 明确包含微信小程序 | 普通越权/一般信息泄露=中危；核心越权/大量敏感=高危 | 越权真实数据≤5 组，严禁批量 |
| 喜马拉雅 SRC | 通用 API/越权规则适用 | 一般越权=中危；大量敏感=高危 | 无法稳定复现、缺关键证据、标题夸张降级 |
| 补天 | 无小程序专项标准，按通用/事件 | 通用漏洞/事件漏洞 | 无法复现、影响不大、重复、厂商权重<1 |
| 漏洞盒子 | 无专项标准 | 企业 SRC 自定义评级 | 预审不通过/信息不全 |
| CNVD | 无专项规则 | 事件型限运营商/党政/重要行业；通用型中危以上+注册资本≥5000 万+10 案例 | 普通商业小程序通常不满足门槛 |
| EDUSRC | 教育行业小程序可收 | 按教育 SRC 定级 | 非教育资产、无影响、无法复现 |

**报告设计含义**：
- 默认 "SRC-ready"：范围/授权、测试账号、复现步骤、请求响应、影响证明、修复建议、数据量说明。
- 高危叙事必须落到大量用户敏感数据、核心业务越权、支付资金损失、框架级影响。
- 报告要能直接转交厂商 SRC/EDUSRC/众测，不按单一平台口径写。

**AI 审计最新实践**：
1. 多 Agent 分工（反编译/敏感/接口/加密/漏洞/报告）。

6. 签名/加密还原：AI 读解包 JS 定位算法→穷举反推/沙箱复现→导出本地 Node 脚本。
7. 边界：混淆/VMP、端到端加密、登录后路径、复杂交互仍限制 AI。

## 6. 差异化卖点

1. **一个包/一个 AppID，打到后端，证据能复现**——竞品要么 SaaS 扫描（黑盒无证据），要么人工（慢贵）。我们把"解包→静态→动态验证→证据→报告→复测"做成一个任务。
2. **不是小程序扫描器，是小程序渗透 Agent**——给可复现攻击链：源码行+真实请求响应+重放脚本+影响证明。
3. **小程序是入口，后端才是战场**——已有 Web/API/云工具链，能把小程序发现转到后端接口、Web、云函数、对象存储。
4. **包不出内网**——本地/私有化，wxapkg 与源码不上第三方 SaaS。
5. **批量资产**——AppID 清单→批量解包/扫描→资产图谱→风险排序。
6. **AI 读源码还原签名，自动重放**——参考 wx-mp-mcp：AI 定位算法→导出 Node 脚本→自动重放/改包。
7. **报告直接能交 SRC/甲方**——按 TSRC/补天/BILISRC/EDUSRC 驳回原因做预检。
8. **覆盖矩阵可对标**——公开 50/65/70+ 覆盖矩阵，比"10000+ 检测项"更可信。
