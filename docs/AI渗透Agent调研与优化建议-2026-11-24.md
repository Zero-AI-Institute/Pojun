# AI 渗透 Agent 全面调研与优化建议（2026-11-24）

> 调研范围：2025-2026 开源项目/商业产品、学术论文与基准、中文社区与公众号实战、Agent 工程模式、本仓架构映射。
> 证据分级：强=公开基准/受控实验/可复现；中=厂商内部评测或大规模生产 telemetry；弱=单一案例/预印本/厂商宣传。
> 结论：**外部化状态 + 分层规划 + 专精技能 + 确定性验证 + 人助兜底**。我们的架构方向正确，差距集中在 5 个结构性缺口。

---

## 0. 执行摘要

1. **行业已从“给工具接 LLM”进入 Harness 工程阶段**。竞争点不是模型，而是状态管理、上下文工程、确定性验证、治理与成本。
2. **全自主在真实场景仍弱**：AutoPenBench 自主 21% / 人助 64%；CVE-Bench 最佳 13%；PentestEval 全自主 3-6%。高分往往是最佳-of-N、人助或预配置靶场。
3. **最稳的结构性增益**：层级规划/攻击树/状态机、外置状态、难度评估与剪枝、独立验证、上下文分层。工具堆叠与“多 Agent”本身会饱和。
4. **开源头部已把“可验证性”做成标配**：Strix 覆盖度账本、Decepticon OPPLAN/RoE/UntrustedOutput、pentest-ai oracle+阴性对照、evilsocket/audit 异模型证伪+可达性 trace。
5. **商业侧两条路线**：确定性验证平台（NodeZero/Pentera/CyCognito）与 AI-native 发现平台（XBOW/Anthropic/OpenAI）。壁垒是“确定性验证资产 + 资产上下文 + 修复闭环”，不是 prompt。
6. **中文社区共识五件事**：独立验证/审计、上下文分层、确定性优先、三层安全边界、成本分层。与我们的“双图+目标闸门+证据链+三层审批”高度同构。
7. **我们已有但被低估**：冷图分层压缩、跨 work/跨任务黑盒、确定性续跳/变体、证据可信度栈、autopilot 三件套。
8. **五个结构性缺口**：覆盖率矩阵三套口径、终态反思未沉淀、跨任务经验只有成功 playbook、工具路由靠静态文案、预算只到意图级。
9. **P0 建议**：覆盖率矩阵一等公民、终态 reflection 节点、任务级预算网关、工具契约容错/幂等、独立 Auditor 最小版（verification_strategy + 只读复核）。
10. **一句话**：把“多 Agent”降级为只读并行侦察，把“长任务”交给事件日志+检查点+预算+收尾，把“智能”集中在 planner 与工具/技能目录，把“可信”押在证据账本与独立验证上。

### 2.2 最值得吸纳的设计（按证据密度）

1. **覆盖度账本**（Strix `coverage.json` 五种结局 + provenance；Decepticon 报告 tested surface/negative results/untested coverage/limitations）——报告“没发现什么”和“为什么排除”。
2. **独立验证 + 阴性对照**（pentest-ai：oracle 重复利用 + control；模型无权给 verified；Xalgorix 独立 verifier；Decepticon CRITICAL/HIGH 要求 2+ 方法 + 等价阴性对照；XBOW deterministic validators）。
3. **异模型对抗验证 + 可达性 trace**（evilsocket/audit：Hunt 用 Sonnet、Validate 用 Opus 专门证伪；Trace 证明 attacker-controlled input 到 sink；Dedupe 按 root cause；Feedback 把可达 trace 变新 Hunt）。
4. **版本化 plan DAG + fact 失效传播**（Decepticon OPPLAN：expected_revision、blocked_by/any_of/required_fact_ids、revoke_plan_fact 传递性 blocked；LuaN1ao Plan-on-Graph）。
5. **每目标 fresh context + 工件外置 + 不信任子 Agent 复述**（Decepticon 每 objective 新上下文；LuaN1ao TaskEnvelope/不可变 artifacts；Strix 父 Agent 读子 Agent 实际 report id，不信 prose）。
6. **预算硬闸 + 工具调用上限 + 优雅终止**（audit `--max-cost-usd` 阶段间与任务内检查；PentAGI 通用 100/受限 20 次工具调用；Decepticon BudgetEnforcementMiddleware）。
7. **不可信输出隔离 + 出口 allowlist + 时间窗**（Decepticon `<UNTRUSTED_TOOL_OUTPUT>` + PromptInjectionShield + TimeWindow + sandbox policy；RAPTOR Landlock/seccomp/Seatbelt + egress allowlist）。
8. **SRC/众测 program profile**（pentest-ai `programs/acme.toml`：rps/scope/excluded/scanners_allowed/allow_race；`--dry-run`；`X-Bug-Bounty` 头；429/Retry-After）。
9. **一任务一攻击类 + gapfill/feedback**（audit Recon 产出 15-50 个窄 Hunt 任务；Gapfill 按覆盖缺口重排）。
10. **发现→确定性回归用例库**（CyCognito 把 AI 发现 hardcode 进确定性测试；audit Dedupe/Feedback；我们已有 retester/续跳）。

### 2.3 商业产品两条路线

- **确定性验证平台**：Horizon3 NodeZero、Pentera、CyCognito。自主规划 + 确定性利用模块 + 攻击路径图 + 修复验证；不靠 LLM 生成 exploit；生产安全记录是壁垒。
- **AI-native 发现平台**：XBOW、Anthropic Project Glasswing/Claude Security、OpenAI Aardvark/Codex Security、Google Big Sleep/CodeMender。强在未知漏洞、代码/内存安全、攻击链；但披露积压、人工 triage、误报/严重度仍需人类。
- **共同点**：证据第一（exploit + 请求响应/攻击路径/复现步骤）；人工介入没有消失，只是前移/后移；壁垒是确定性验证资产 + 资产上下文 + 修复闭环。
- **国内**：微步 RedAgents 走“多引擎聚合”路线（接入 ARTEX Pro/衍迹/燕巡/CyberStrikeAI 企业版），卖“不被单一供应商锁死”；奇安信 AI 加特林 4 智能体 + 6000+ 插件；长亭无锋产品+服务；知道创宇 AI 服务；360 图龙锋多智能体蜂群；腾讯朱雀 A.I.G 做 Agent/MCP 安全体检。
- **需核实**：GitHub 上 `BaaRai/ARTEX`（17,453 stars，AGPL-3.0，upstream Autumn-27）与本仓命名/来源关系，建议法务/品牌层面确认；不影响技术结论。

### 2.4 五个判断

1. 2026 竞争点从“能不能调用工具”转向**可验证性与治理**。
2. 商业壁垒不是模型，是**确定性验证资产 + 资产上下文 + 修复闭环**。
3. 评测与实战仍脱节：CTF 高分 ≠ 带 WAF 的真实渗透。
4. 中国市场出现“聚合平台”打法，多引擎交叉验证比单引擎更容易形成渠道壁垒。
5. 我们的差异化在**双图血缘、goal_met 闸门、MITM 四类证据、漏洞情报时间流、公文级 Word**；缺口在 oracle 阴性对照、覆盖度账本、plan DAG 版本化、SRC program profile、预算硬闸、不可信输出隔离。

### 3.2 什么真的有用（有数字）

1. 层级规划/任务分解：HPTSA 4.3× pass@1；AutoPT 41% vs 22%；PentestGPT v2 91% vs 61%。
2. 外置攻击树/状态机：PentestGPT v2 消融 54→68→77→85；PSM +19；PTG 子任务 49.05%→69.05%。
3. 难度评估/剪枝：TDA 把 Type B 失败 58%→27%；TDA-EGATS +9。
4. 状态/反思/摘要：HackingBuddyGPT 33%→66%；EnIGMA Summarizer +2.5；去 Reasoning 只剩 53.6%；memory +8。
5. 工具/技能层：Tool +14（XBOW），但 13 台 +1、GOAD 0；不完整命令 4.46→0.13。
6. 确定性验证：XBOW 85%；CVE-Bench v2 修复评分漏洞后 -32.5%；AIxCC accuracy multiplier。
7. 测试时扩展/重试：87% pass@5 vs 40% pass@1；28.9%@1 vs 66.7%@30（约 $45/task）。
8. 人助：21%→64%，最稳定提升手段。

### 3.3 被高估

- “多 agent”本身（无层级/共享状态可能不如单 agent；HPTSA 去掉层级 pass@1 低 13×）。
- PentestGPT Generation 模块（主要提升操作精度）。
- “大上下文”（8k 与 128k 均 66%；40% context load 是理想窗口，60% 准确率 94%→78%，80% 61%）。
- RAG/经验复用（同漏洞泄漏 vs 可迁移经验）。
- 基准 SOTA（XBOW-104 过时；Cybench 2024 模型）。
- “全自主”（高分多为最佳-of-N/人助/预配置靶场）。
- 工具数量（38 工具 XBOW +14，但长程收益迅速衰减）。
- 成本叙事（CAI 156× 便宜但 hard/insane 更慢；AutoPT $0.0099 是预配置 VulHub）。

### 3.4 12 条工程结论（压缩）

1. 评测固定 scaffold/模型/预算/重试，否则数字没意义。
2. 分层规划/攻击树/状态机是最稳结构性增益。
3. “多 agent”本身不是增益；角色专精+层级+共享状态才是。
4. 上下文/状态管理是长程第一瓶颈。
5. 难度感知与剪枝是 2026 关键增量；工具堆叠会饱和。
6. 工具层解决能力型失败，不解决规划型失败。
7. 自主 vs 人助差距大；全自主真实场景仍低。
8. 必须同时报告 pass@1/pass@k；重试有效但成本线性。
9. 成功判定必须确定性验证/环境状态；LLM 自评和宽松评分会造假。
10. RAG 有收益，但要分离同漏洞泄漏与可迁移经验。
11. “便宜”不等于总成本低；时间/人工/验证/误报都要计。
12. 真实漏洞发现集中在白盒/有描述/可验证场景；开放未知漏洞仍是前沿。

## 4. 中文社区实战

### 4.1 共识五件事

独立验证/审计、上下文分层、确定性优先、三层安全边界、成本分层。

### 4.2 10 条经验

1. 先定义“可验证的完成”（flag/effect_proof/poc_crash/oracle 四类验证策略，独立引擎裁决）。
2. 执行者与审计者分离（Auditor 只读；Executor 每轮新上下文；Harness 唯一状态写入方；Judge 便宜模型结构化 JSON）。
3. 证据必须包含业务语义（公共/私有接口、设计内/设计外；仅 HTTP 证据不够）。
4. 图要完整，渲染视图分层（Index ≤3KB / Summary / Raw；hint 全量、失败方向保留、fact 只留最近）。
5. 价值评分 watchdog，而非固定超时（300s 基线 + 新增 fact/工具成功率/高价值突破评分；SOFT_WARN→终止；终止前回填）。
6. 确定性代码做调度/提交/审批/状态写入（LLM 只做语义判断；Decision Router 60-80% 规则）。
7. 工具接口按“LLM 一定会乱传参”设计（5 层容错 + `vuln_type:endpoint:param` 幂等 + MCP 健康检查/0-turn/finally/错峰）。
8. Skill 场景化、按需加载、可度量（4000 行拆 FuzzZero/FuzzOne；31% session 零调用）。
9. 误报治理靠对照实验+业务上下文+允许不确定（多模型 COT + 原子化任务 + RAG + Workflow；三分法）。
10. 成本按角色分层，用单位有效发现成本衡量（planner 强/worker 中/judge 便宜；单目标预算熔断）。

### 4.3 高频坑

重复劳动/死磕（flask-unsign 74 次）、上下文爆炸（43 session 210M token）、工具失败（46.5% 无报告）、范围/越权失控（masscan 扫 C 段封 IP）、只扫描不验证（66.7% 误报）、自我宣布完成、知识有但不用（31% 零 Skill 调用）。

## 5. Agent 工程模式

### 5.1 模式取舍

| 模式 | 结论 | 优先级 |
|---|---|---|
| 单线程线性 agent + 压缩 | 默认基线，避免多写者冲突 | P0 |
| Planner-Executor + 滚动重规划 | planner 无状态、计划版本化；连续无进展重规划 | P0 |
| Supervisor + 隔离子 agent | 只读并行，写入单线程；子 agent 返回 1-2k token | P0 |
| 图/DAG + 人工闸门 | LangGraph checkpoint / ADK Go 2.0 可参考 | P1 |
| 对等 agent 团队 | token 高、恢复有限，收益不确定 | P2 |
| 稳定前缀 + append-only | 缓存命中是成本第一杠杆（84% 中位） | P0 |
| 两段式压缩（可逆→摘要） | 工具结果 full/compact 双格式；先压最老 50% | P0 |
| 结构化笔记 + 文件系统即记忆 | JSON schema + progress；不急于上向量库 | P0 |
| Skills 渐进披露 | 元数据 ~100 token，正文 <5k，引用按需 | P1 |
| 工具目录少而深 | 命名空间 + 合并 + 默认 20-30 + 结果 25k 上限 | P0 |
| 工具搜索/PTC | Tool Search -85% token；PTC -37% | P1 |
| 证据账本 + 独立报告 pass | 内容寻址 + claim→source + 无证据降级 | P0 |
| 持久化执行/checkpoint | 事件日志 + 幂等 + resume prompt + typed reason | P0 |
| 预算治理 + 模型路由 | turns/USD/wall-clock；80% 预警；角色分层 | P0 |
| HITL + 沙箱网络作用域 | 高风险动作审批；scope 前置 + egress 双层 | P0 |
| OTel + 轨迹评测 | invoke_agent/plan/execute_tool span；pass^k | P1 |

### 5.2 10 条做法（压缩）

1. 稳定前缀当一等公民（固定字段序、prefix hash、缓存命中率）。
2. 上下文两段式缩减（full 落 artifact，compact 只留 handle；先压最老 50%）。
3. 外部状态用 schema（plan.json/progress.md/findings.jsonl；只改状态字段）。
4. Planner 独立成 agent，用进度账本重规划。
5. Worker 交接契约（最小上下文、结构化结果+artifact、只提案不写全局）。
6. 工具目录少而深（命名空间、任务级合并、延迟加载、结果上限）。
7. Skills 渐进披露 + 压缩后重注入。
8. 证据账本 + 独立报告 pass + 完成闸门。
9. 持久化执行（事件日志、幂等、resume、typed reason）。
10. 预算 + 无进展检测 + 强制收尾。

### 5.3 反模式

固定长计划、并行写共享状态、每个 CLI 1:1 包工具、过早不可逆摘要、没有预算/停止条件的自主循环、把专用记忆服务当第一优先级。

## 6. 本仓现状与差距

### 6.1 已有但被低估的 5 个能力

1. **冷图分层压缩**：compaction.go（cold stamp、minor/major、连通块）、coldgraph.go（热集/结构冷区）、expand_digest；带复活检查/签名复用/并发冷却退避。
2. **跨 work/跨任务可观测黑盒**：get_worker_output/trace/search/list、related_task_overviews、exploration_sources 继承视图。
3. **确定性攻击链续跳与变体派发**：chain.go（high/critical 后按 dimension 派继任意图）、variant.go（validate pass + simhash 同簇派生 1-2 条）。
4. **证据可信度栈**：逐字回验 + EvidenceGrade + SRC 13 项 + validate_finding/validators。
5. **Autopilot 三件套**：停滞看门狗（facts+findings 指纹）、连续停滞 deadline 延长、目标续杯阶梯 + 收尾抑制。

### 6.2 五个结构性缺口

1. **覆盖率矩阵三套口径**：planner prompt 手写 10 类、引擎 6 类正则、graph_overview 只算被 fact 碰过的资产；dimension 字段已存在但只用于去重。
2. **终态反思未沉淀**：只有 `exhausted 且零写回` 触发硬编码 review；done/blocked/timeout/stopped 无 lesson 节点。
3. **跨任务经验只有成功 playbook**：只覆盖 validator PASS 的 critical/high，只注入 planner，worker 看不到；失败路径不存。
4. **工具路由靠静态文案**：tool_usage/skill_usage/guard 归因只用于统计页；无“某维度最常成功/高 error/被拦最多”的先验。
5. **预算只到意图级**：planner 轮/压缩/reporter/复测不在预算内；无 USD/token 任务级/角色级预算与降级。

### 6.3 能力矩阵（对商业/开源）

| 维度 | 我们的位置 |
|---|---|
| 工具编排 | 66 件精选 + hostd 串行 + MCP 按需；较克制（优于工具超市） |
| 长任务与恢复 | 后台作业 + 断点续跑 + compaction；强 |
| 证据/PoC | MITM 四类证据 + sha256 + 报告引用；强 |
| 误报治理 | 多键去重 + L1-L4 证据分级 + 对抗自检；中强，缺阴性对照 |
| 报告质量 | 公文级 Word + 目标达成 + 复测；强 |
| 成本/token | 三通道 + 角色路由 + 缓存；强，缺硬预算闸 |
| 可观测性 | UI 内联 activity + 任务日志；中强 |
| 权限/审批 | deny/judge/ask 三层 + 写回守卫；强，缺时间窗/速率 |
| 模型选择 | 多通道 + 角色模型；强 |
| 批量任务 | 任务队列/批量报告；中强，缺跨任务调度视图 |

**定位**：证据链 + 目标闸门 + 情报时间流 + 中文交付已领先多数开源；与商业产品比，缺“确定性验证资产”和“企业治理外壳”，不是 Agent 本身。

### 不建议做（评估过）

1. 150+ 工具 MCP 大超市（HexStrike 式）：上下文爆炸、选择错误、root/命令面风险；保持 66 件精选 + hostd + MCP 按需。
2. 无界 sub-agent 图（Strix 式）：无预算/去重/覆盖度三件套时成本与重复失控；只做有界 delegation。
3. CTF writeup RAG/auto-prompt 堆叠：CRAKEN Graph-RAG 22% 与 D-CIPHER 持平；工具齐全时 auto-prompt 反而降分；预算投真实复盘/证据库。
4. 照搬 16 角色红队编制（Decepticon 式）：复杂度高、低频能力多；只吸收 RoE/OPPLAN/middleware slot/安全关键槽。
5. 把 Claude Code/Codex CLI 当生产运行时：ToS/遥测/凭证边界/多租户隔离/版本漂移/审计 SLA 不可控；生产走 API 网关 + 容器隔离。

## 9. 验收标准（P0）

- **覆盖率矩阵**：planner 态势、引擎 nudge、autopilot 续杯、docx 报告四处数值来自同一查询；报告含“覆盖与排除”章节；重复派单率下降。
- **Reflection**：每个终态意图在图上有一条 lesson（intent_id/dimension/terminal reason/写回计数/工具分布/Guard 拦截/失败特征）；planner 下轮可见 recent_lessons；worker 注入同资产/同维度最近 lesson。
- **预算**：任务级 tokens/USD/wall-clock；80% 预警并切便宜 profile；100% 终态 `budget` 与 timeout 可区分；llm_transition 可审计。
- **工具契约**：report_finding/record_fact 5 层归一 + 幂等键；重复提交不产生新 finding；MCP 启动健康检查/0-turn/finally；worker 错峰。
- **Auditor**：critical/high 有 verification_strategy；只读 auditor 独立复核并签 pass/fail/uncertain；未通过进“待验证”，不进交付报告；阴性对照可复现。

## 11. 总结

**行业最好的形态不是“更强的模型 + 更多 Agent”，而是“更硬的 Harness + 更真的证据 + 更早的收尾”。**
我们的架构方向正确，已有大量被低估的能力；P0 五项（覆盖率矩阵、终态 reflection、任务预算、工具契约、独立 Auditor）是投入产出比最高的下一步。
