# 代理与出口链路

> 适用版本：v0.4.83+。目标流量 = worker 对授权目标的请求；平台自身流量 = LLM/情报同步/装机等。

## 一、三条出口路径

| 场景 | 出口 | 说明 |
|---|---|---|
| 流量捕获 **开** | 本地 MITM（`traffic`） | 所有目标流量进录制库；MITM 上游再按「代理池 → 全局代理 → 直连」选择 |
| 流量捕获 **关**、代理池有可用条目 | 池内挑一个上游 | 每个 Agent 构建时固定一个出口（`ProxyAddr()`）；任务内 Bash/原生工具一致 |
| 流量捕获 **关**、池空/全熔断 | 全局代理 → 直连 | 旧行为；严格出口开启时改为失败（哨兵 `127.0.0.1:1`），不回退直连 |

**严格出口**（`egress_strict_proxy`，默认关，代理池页开关）：池已配置但全部熔断时，目标请求直接失败，绝不暴露真实 IP。另有 `traffic_direct_record_fallback`（默认关）允许「直连但仍录制」——牺牲 IP 隐藏换证据连续性，仅运维显式开启。

## 二、各执行面的代理覆盖（v0.4.83 修复后）

| 执行面 | 代理来源 | 状态 |
|---|---|---|
| Bash 子进程（curl/python/git/feroxbuster…） | `proxyEnv()`：`HTTP(S)_PROXY` / `ALL_PROXY` / `CA` + `EGRESS_PROXY` | ✅ |
| 原生 `http_request` / `session_login` | `ToolSet.SetEgressProxy`（worker/planner/mainagent 构建时注入） | ✅ v0.4.83 修复（此前是死代码，直连） |
| `job_start` 后台作业 | `mergeProxyEnv(os.Environ(), egressProxy, CA)` | ✅ v0.4.83 修复（此前只取 os.Environ） |
| `run_script` / `poc_scaffold` / 自定义工具 | 交给 Bash 运行，继承 `proxyEnv` | ✅ |
| sqlmap / ffuf / httpx / dalfox（手工命令） | 对 env 支持不稳，**必须显式传参**：worker 提示词已要求用 `$EGRESS_PROXY` | ⚠️ 靠提示词，非强制 |
| `scan_with_nuclei`（工具组命令） | `ToolSet.SetEgressProxy` → `ScanArgs.Proxy` → 命令自带 `-proxy`（空代理不加） | ✅ 代码强制（本版起；server 级注册表除外，见下） |
| nuclei（手工命令） | worker 提示词要求 `-proxy "$EGRESS_PROXY"`；server 级 domainReg 实例无 `egressProxy`，见排障 4 | ⚠️ 靠提示词，非强制 |
| Monitor（SDK 后台工具） | SDK SpawnSpec 不带 Env | ❌ 已知缺口，目标流量请用 `job_start` 或 Bash 后台 |
| enrich HTTP 补全 | `m.ProxyAddr()` | ✅（DNS/UDP 无法走 HTTP 代理） |
| browser MCP | 捕获开时 `--proxy-server=MITM` + CA | ✅ |
| notify / vulnintel / selfupdate / hostd | 维护代理或直连（平台自身流量，故意不进目标捕获） | ✅ |

> 已知缺口（本版不修）：`server/assembly.go` 的 `buildDomainReg`（L480-491 一带）用 `NewToolSet(nil,"")` 建实例且永不调用 `SetEgressProxy`。该注册表只服务不持有 per-task ToolSet 的 Auto/自定义 agent（见 `AllDomainTools` 注释），绑到这些 agent 时 `scan_with_nuclei` 不会带 `-proxy`。chat/mainagent 路径的 ToolSet 已注入 `egressProxy`，不受影响。

合并环境变量时先剔除父进程同名键：POSIX 下重复环境变量以第一条为准，直接 append 会让子进程仍读到宿主旧代理。Windows 环境变量名大小写不敏感，统一保留大写键。

## 三、Clash / mihomo 内核

- 页面：系统 → Clash 节点管理（`/system/proxypool/clash`）
- 安装：GitHub 官方源 + 镜像加速（`gh-proxy.com` 等，可用 `proxypool_mihomo_mirrors` 覆盖）+ 自定义 URL/本地文件/PATH 四路；SHA256 校验、断点续传
- 启动：订阅 YAML 或 URL → 重写配置（只留随机 mixed-port、绑回环、规则收敛为单条 `MATCH,<出口>`、关 geo 下载）→ 等待端口 + 真实 HTTP 验活 → 入口地址以 `mihomo-local` 写入代理池
- 出口模式：固定组 / 固定节点 / 负载均衡 / url-test / fallback；`external-controller` 只绑回环且每次随机 secret，用于节点延迟测速
- 健康检查：本机 mihomo 上游全部失败时自动从落盘配置拉起；熔断状态跨重启持久化（`proxy_pool_break_state`）

## 四、代理池

- 条目：`http/https/socks5://[user:pass@]host:port`，支持名称/权重/启停
- 策略：`round_robin` / `sticky_host` / `sticky_host_random` / `random`
- 熔断：连败 5 次冷却 10 分钟；主动健康检查默认 10 分钟一轮、熔断 30 分钟；agent 可用 `proxy_status` / `proxy_report` 查询与上报
- 导入：逐行解析 host:port / URL / host:port:user:pass；默认导入前验活，坏行不导入
- 捕获关闭时：每个 Agent 构建时 `ProxyPoolPick("")` 固定一个出口；池变更后自动重建 Agent（`refreshAgentsForEgressChange`）

## 五、SSH 跳板

- 页面：系统 → SSH 跳板（`/system/egress`）
- 密码/私钥经凭据保险库（XChaCha20-Poly1305，主密钥 `data/vault.key` 或 `POJUN_VAULT_KEY`）加密存储，API 只回 `credential_id`
- 启动后本地监听随机 SOCKS5，`use` 一键把 `socks5://127.0.0.1:<port>` 加入代理池（`ssh-jump` 条目）
- 与 Clash 节点可并存；停用即从池移除

## 六、排障

1. 目标请求不通：先 `proxy_status` 看池可用数/熔断/严格出口；再确认是本机出口问题还是目标不可达
2. 原生工具不走代理：确认 `http_request` 在 worker/planner/mainagent 内调用（v0.4.83 起自动注入）；检查 `EGRESS_PROXY` 是否在 Bash 环境里
3. 后台作业不走代理：`job_start` 已继承；Monitor 不继承，改用 job_start
4. sqlmap / ffuf / httpx / dalfox / 手工 nuclei 直连：这些工具对 env 支持不稳，代理靠提示词要求显式传参（sqlmap `--proxy="$EGRESS_PROXY"`、ffuf `-proxy "$EGRESS_PROXY"`、httpx `-http-proxy "$EGRESS_PROXY"`、dalfox `--proxy "$EGRESS_PROXY"`、手工 nuclei `-proxy "$EGRESS_PROXY"`）；配置了出口代理仍直连时先核对命令。用 `scan_with_nuclei` 时先看 `run_with_bash` 里有没有 `-proxy`（本版起会自动带，不是漏配；若确实没有，说明走的是 server 级直连实例，见上方已知缺口）。
5. 严格出口开启后全部失败：属预期（fail-closed）；恢复上游或临时关闭严格出口

## 七、任务出口回执（issue #39）

任务构建 Agent bundle 时，把 worker/planner/mainagent 三处 `SetProxy` 的实际注入值
与当时的出口策略记录为只读快照，写入 `tasks.egress_snapshot`（写入前脱敏）。
任务详情「总览」展示为只读卡片；API 为 `GET /api/tasks/{id}/egress`。

- **出口类型**：`recording_proxy`（捕获开，本地记录代理）/ `proxy_pool` / `global_proxy` /
  `direct` / `strict_block`（严格出口哨兵，请求必然失败）。判定与 `Manager.ProxyAddr()` 分支一一对应，
  并由 `server/task_egress_test.go` 用真实池/熔断/全局代理状态与 `ProxyAddr()` 返回值对拍。
- **capture 开关**：`enabled` 是设置值，`injected` 表示三个 Agent 真的被注入了记录代理地址
  （traffic 子系统存在），`effective` 表示记录代理确实在监听（`Traffic.Running()`：`Start` 已进入
  且尚未返回，端口占用等启动失败会立即回落为 false）。三者不一致时卡片会明确提示
  「监听未就绪 / 记录代理不可用」，不会把 `traffic != nil` 当成「录制中」。`ca_present` 是录制信号。
  注意 `effective=true` 也不等于全部流量被录制：MITM 拦截失败的 host 会透明隧道（fail-open）
  放行且不产生录制，`capture.note` 会写明该盲区。
- **按角色记录**：三个 Agent 各调用一次 `ProxyAddr()`，捕获关闭 + `round_robin`/`random`
  时可能固定到不同上游（`roles_uniform=false`）；`sticky_host*` 与捕获开启时一致。
- **上游声明**：仅捕获开启时给出 MITM 的上游策略（池/全局/直连/严格阻断）与构建时可用条目数；
  真实出口 IP 由 MITM 逐请求按目标 host 选择，**构建期不可知**（字段 `observed.known=false`）。
- **生效 UA**：按执行面声明 `platform_fixed`（如原生 http_request 的 Chrome/131）/
  `runtime_default`（curl 系随运行镜像版本）/ `tool_own`（WebFetch/nuclei/browser MCP）
  与覆盖入口；任务级没有 UA 配置，回执不声称目标侧实际收到的头。
- **语义**：404 = 任务不存在/已删除/已归档；200 `built=false` = 尚未构建过 Agent；
  200 `built=true` = 构建时快照（非实时，设置变更后任务下次构建才刷新）。
- **安全**：代理地址只保留 scheme/host/port 与 `has_auth` 布尔，用户名/密码/路径/查询串
  一律丢弃；解析失败只标记 `parse_ok=false`，不回显原文。归档时显式清空，恢复不回填。
- **后续**：#25 `exchanges.task_id` 可把「真实出口 IP / 本任务已录制流量条数」补进回执；
  任务级出口/UA 配置属 #16 的后续阶段。
