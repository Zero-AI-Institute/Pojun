# 小程序渗透能力调研与落地方案（2026-11-23）

> **更新说明**：本文为初版调研。后续深度实测发现 KillWxapkg 存在包内路径穿越、失败 exit 0、WXML 丢绑定三项问题，工具链已改为「自研安全解包器 + wedecode/unveilr 质量解包 + KillWxapkg 沙箱兜底」。完整结论以 `docs/小程序渗透能力完整方案-2026-11-23.md` 与 `docs/小程序包格式与工具链深调研-2026-11-23.md` 为准。

> 目标：给平台新增「小程序渗透」能力。用户初步设想：把 PC 端微信缓存的小程序包（wxapkg）
> 通过对话附件传到平台，布置任务后 agent 自动反编译与相关处理。
> 结论先行：**设想完全可行，且平台侧改动比预期小**——上传通道已存在，缺的是解包工具、
> 一个复用 js_audit 扫描器的入口工具、一个方法论技能与一个任务 Playbook。

---

## 一、包格式与获取（用户操作指引，写进技能）

### PC 端微信（主路径）
- 缓存目录：`WeChat Files\Applet\{appid}\{version}\__APP__.wxapkg`（主包）+
  同目录其他 `.wxapkg`（分包）。微信 3.x/4.x 目录略有差异，技能里给 glob 提示。
- **PC 包是加密的**：文件头 `V1MMWX`，AES-CBC（PBKDF2(appID, "saltiest", 1000轮,
  SHA1) 派生密钥，固定 IV "the iv: 16 bytes"）解前 1024 字节 + appId 倒数第二字节
  XOR 解余下（已用 KillWxapkg 源码 decrypt.go 核实）。**agent 只需知道 AppID**
  （缓存目录名即 AppID）即可全自动解密，无需人工。
- 手机端包不加密（Android /data/data/com.tencent.mm/MicroMsg/{user}/appbrand/pkg/，
  iOS 沙盒内），但获取需要设备/root——技能标注为备选路径。

### 包内关键产物
解包后得到：`app-config.json`（全部页面路由与配置）、`app-service.js`/页面 JS
（业务逻辑）、`*.wxml`/`wxss`（界面结构）、`app.json`（tabBar/request 合法域名参考）。

### 其他平台（低优先）
支付宝（.apkg/.tar，工具少且维护差）、抖音/百度/QQ 小程序各有格式——v1 只做微信，
其他平台留待需求出现。

## 二、解包工具选型（已核实）

| 工具 | 语言 | 许可证 | stars | 活跃度 | 形态 | 判定 |
|---|---|---|---|---|---|---|
| **Ackites/KillWxapkg** | Go | MIT | 6058 | v2.4.1 (2024-09)，代码稳定 | 纯 CLI | **首选** |
| wux1an/wxapkg | Go(Vue/Wails GUI) | 无许可证 | 4413 | 2026-04 | GUI | 不适合无头服务器 |
| unveilr（AnkioTomas fork） | TypeScript(Node) | 未声明 | 175 | 2025-12 活跃 | CLI+Web | 备选（Kali 有 node24） |
| wxappUnpacker 系 | JavaScript | 各 fork 不一 | 老牌但停维护 | — | CLI | 不选 |

**KillWxapkg 选型理由**：纯 Go 与平台后端同语言（可直接 go build 产出 linux 二进制
纳入 hosttools，官方 release 只有 darwin/windows 无 linux——hosttools 条目用
KindScript 从源码编译）；MIT 许可证允许集成；CLI 完全自动化：
- `-in <文件或目录>` 自动检测已解密/未解密（读 0xBE/0xED 头），未解密自动解密
- `-id <AppID>` 解密密钥派生输入（缓存目录名即 AppID）
- `-restore` 还原小程序原始工程目录结构；`-pretty` 美化；`-sensitive` 导出敏感数据
  （自带 sensitive_data.json，规则可自定义）
- `-repack` 重打包（改包后配合 Hook/F12 调试，Windows-only 功能标注为可选）

## 三、渗透方法论（授权场景，写进技能 references）

业界公认流程（综合 freebuf/知乎/奇安信等多篇方法论 + 内部版 src-hunting 已有积累）：
1. **解包**：wxapkg → 源码树（app-config.json 是地图）
2. **信息提取**：全部 HTTP(S) 接口与域名（request 合法域名/业务域名/web-view URL）、
   硬编码密钥（AppSecret/AKSK/JWT/加密 key）、云开发环境 ID（cloudbound）、第三方
   SDK key（高德/百度/极光等）
3. **登录态分析**：wx.login → code → code2session 流程、openid/session_key 的存储与
   传输、自定义身份体系
4. **接口测试**（回到平台既有强项）：未授权访问（删 token/openid 重放）、水平越权
   （换 id）、签名绕过（重放/时间戳）、批量遍历
5. **云开发专项**：未授权 cloudfunction 调用、云数据库 open 读、存储桶遍历
6. **抓包联动**：PC 端微信自带流量可走平台录制代理（配合强制代理环境变量），或
   手机端代理——小程序 SSL pinning 少见，抓包成功率高于 APP
7. **web-view/H5**：包内 web-view 域名 → 平台 Web 渗透管线接续

**平台已有积累直接复用**：src-hunting 技能的 authbypass-test.md（小程序码/跳转码签发、
openId 空/假值、云函数 Registry）、idor-test.md（小程序打包 JS 写死 token）、
打穿短表.md 三处已有小程序专项条目——方法论技能只需写「解包+提取」前置段，
测试段直接引用现有 references。

## 四、平台适配（现状摸底结论：改动小）

**已存在（不需要做）**：
- 附件上传：任务创建页 pickFiles → staging uploads/ → 绝对路径写进 description；
  对话页 chatUpload(task) → composeAgentMessage 把绝对路径清单拼进消息。
  wxapkg 包（几 MB～几十 MB）直接可传，128MB 上限足够。
- 方法论技能模板：apk-reverse 的 SKILL.md+scripts/decode.sh+references 结构完全同构
- 扫描器复用点：js_audit.py 的 secret_scan（7→13 条正则）/endpoint_scan/
  write_sources/OSV 比对全是纯函数，入口只差「本地目录」输入

**需要做（四件）**：
1. **hosttools 加 killwxapkg 条目**（KindScript 从源码编译，Go 构建 linux 二进制；
   或作为 mini-program skill 的 scripts/ 自装逻辑）——`db/hosttools.go`
2. **js_audit 加「本地目录/文件」输入模式**：入参加 `dir`（与 urls 二选一），跳过
   网络抓取直接对解包产物跑 audit_js 的 map/secret/endpoint 扫描 + OSV——
   `agent/tools_jsaudit.go`（Python 侧加个 walk 入口，纯函数全部复用）
3. **新增 `skills/mini-program/` 技能**（仿 apk-reverse 结构）：
   - SKILL.md：解包（KillWxapkg 用法+AppID 说明）→ 信息提取 → 与平台衔接表
     （同 apk-reverse 的表格）→ 平台既有小程序测试条目引用
   - scripts/miniapp_unpack.sh：定位 uploads/ 下 wxapkg → killwxapkg -restore
     -pretty -sensitive → 输出源码树+endpoints+secrets 摘要（自装 killwxapkg）
   - references/：获取指引（PC 缓存路径/手机端）、方法论 checklist
   - 绑定到 worker + pentest（toolcatalog 与 Playbook seed 同款模式）
4. **新增任务 Playbook「小程序渗透」**（task_playbook_seed.go 追加一条，settings
   flag 升批次）：解包 → 静态提取接口/密钥落 fact/insert_assets → 接口测试
   （转 http_request/auth_request/diff_responses）→ 抓包/流量联动 → 报告

## 五、关键设计决策

- **解包产物位置**：`<taskDir>/miniapp/<appid>/`（与 apk-reverse 的输出约定一致，
  不落 /tmp），报告与证据引用稳定路径
- **不做手机端自动拉包**（需设备/root，MVP 排除）；不做 wxapkg 重打包与 Hook
  （Windows-only，标注为可选进阶）
- **分发合规**：KillWxapkg MIT；wxapkg 解密密钥派生算法公开已久（BlackTrace/
  pc_wxapkg_decrypt 2019 起开源），平台集成无法律问题
- **解密输入**：AppID 从缓存目录名/文件名提取，agent 也可从 app-config.json 或
  用户消息中读取——多路径兜底

## 六、验证方式

1. 单测：miniapp_unpack.sh 对一份真实/合成 wxapkg（可用 KillWxapkg -repack 或
   手工构造 header）跑通解包+扫描输出
2. 端到端：本机实例上传一个 wxapkg → 建任务 → agent 走 miniapp_unpack →
   js_audit 目录模式 → record_fact/insert_assets → 报告
3. Kali 部署核验版本行 + killwxapkg 工具在位
