# 微信小程序包格式与工具链深度调研（2026-11-23）

> 基于公开仓库源码、官方文档、Issue 与本机实测。样本为公开 V1 包（339,952 字节），4.x 行为需在授权目标复验。

---

## 0. 结论摘要

### 包格式
- 明文 `.wxapkg` 是自定义二进制容器（非 zip）：`0xBE` + 4B 保留 + 4B 索引长度 + 4B 数据长度 + `0xED` + 4B 文件数，随后索引区/数据区。
- PC 微信 3.x/4.x 的 `__APP__.wxapkg` 普遍带 `V1MMWX` 外壳：PBKDF2-HMAC-SHA1(appid, "saltiest", 1000, 32) → AES-256-CBC（IV `"the iv: 16 bytes"`）解前 1024B；剩余字节与 appid 倒数第二个字符 XOR。
- 截至 2026-11 无可靠 `V2MMWX`/`V3MMWX` 证据；工具里的 V1-V4 指**包内容类型**，不是加密版本。所谓 V3 GCM 仅见于不可信项目。
- Android/iOS 包通常明文 `0xBE`，需 root/越狱；macOS 3.8.0+ 通常明文，<3.8.0 为 AES-ECB + 尾部 tag，需 Frida 提 key。
- 开发者工具缓存不是稳定取包来源（只有运行时文件系统/基础库，不是完整业务包）。

### 三个必须先处理的工程风险
1. **KillWxapkg v2.4.1 包内路径穿越**：构造文件名 `../evil_poc.txt`，实测写到输出目录之外。必须解包前校验索引文件名或沙箱运行。
2. **KillWxapkg 失败 exit 0**：错误只写日志；自动化必须校验产物（首字节、app.json、文件数、WXML 非空率），不能只看退出码。
3. **WXML 还原丢绑定**：实测 KillWxapkg 输出 `<view class="title"></view>`，丢失 `{{config.total}}`；unveilr/wedecode 保留。安全审计不能只看文件数量。

## 1. 包格式

### 1.1 明文结构（大端）

```
偏移 0    1B   0xBE
偏移 1    4B   info1（通常 0）
偏移 5    4B   indexInfoLength
偏移 9    4B   bodyInfoLength
偏移 13   1B   0xED
偏移 14   4B   fileCount
偏移 18   N    索引项
...            数据区
```

索引项：

```
uint32 nameLen
char   name[nameLen]   // UTF-8，通常 "/" 开头
uint32 offset
uint32 size
```

实测：`BE 00000000 000002D5 00052D0D ED 00000015`；indexLen=725、bodyLen=339213、fileCount=21；`14+725+339213=339952`；首文件 offset=739=14+725（绝对偏移）。

兼容变体：
- `indexInfoLength` 可能不含 4B fileCount → 同时尝试 `14+indexLen+bodyLen==size` 与 `18+indexLen+bodyLen==size`。
- offset 可能是绝对偏移或相对数据区；用首文件 offset 是否等于 `14+indexLen` 判断。
- 数据区可能重叠/复用（多文件引用同一段数据），不要假设连续。
- 文件名可能以 `/` 开头，含 `__plugin__/`、`plugin-private://`、`__APP__/`；目录不单独登记。
- UTF-8；旧工具在 Windows 可能转 GBK。

最小校验：

```python
assert data[0] == 0xBE and data[13] == 0xED
index_len = int.from_bytes(data[5:9], "big")
body_len  = int.from_bytes(data[9:13], "big")
assert len(data) in (14 + index_len + body_len, 18 + index_len + body_len)
```

### 1.2 V1MMWX 解密

```
"V1MMWX" (6B)
AES-256-CBC 密文 1024B   # 明文前 1023B + 1B 填充
XOR 密文（剩余）
```

```python
key = PBKDF2-HMAC-SHA1(appid.encode(), b"saltiest", 1000, dklen=32)
iv  = b"the iv: 16 bytes"
head = AES-256-CBC-decrypt(key, iv, data[6:6+1024])[:1023]
xor_key = ord(appid[-2]) if len(appid) >= 2 else 0x66
tail = bytes(b ^ xor_key for b in data[6+1024:])
plain = head + tail
```

- appid 是小程序 AppID（`wx`+16 hex），**不是 wxid**；填错只出乱码不报错。
- 解密后校验 `plain[0]==0xBE`、`plain[13]==0xED`、`14+indexLen+bodyLen==len(plain)`。
- 加密文件通常比明文大 7B（6 magic + 1 填充）；实测 339,952→339,959，解密后逐字节一致。
- 只有前 1023B 有效，最后 1B 是填充，不能全拼。

### 1.3 路径（按平台）

**Windows 3.x**
```
C:\Users\<user>\Documents\WeChat Files\Applet\<appid>\<version>\
  __APP__.wxapkg / __FULL__.wxapkg / __SUBCONTEXT__.wxapkg / _pages_xxx_.wxapkg / plugin.wxapkg
```
通常 V1MMWX；文件夹名即 AppID；publicLib/publicTestLib 是基础库。

**Windows 4.x（Radium）**
```
C:\Users\<user>\AppData\Roaming\Tencent\xwechat\radium\users\<userhash>\applet\packages\<appid>\<version>\
C:\Users\<user>\AppData\Roaming\Tencent\xwechat\radium\Applet\packages\<appid>\<version>\
C:\Users\<user>\AppData\Roaming\Tencent\WeChat\radium\Applet\packages\<appid>\<version>\
```
- `xwechat_files` 是聊天文件目录，通常不含 wxapkg。
- 仍普遍 V1MMWX；分包按需下载，未进入的页面不落盘。
- 两处 radium 路径都可能存在，需递归扫描。

**macOS**
```
~/Library/Containers/com.tencent.xinWeChat/Data/.wxapplet/packages/<appid>/<version>/__APP__.wxapkg   # 3.x
~/Library/Containers/com.tencent.xinWeChat/Data/Documents/app_data/radium/users/<hash>/applet/packages/<appid>/<version>/  # 4.x
~/Library/Containers/com.tencent.xinWeChat/Data/Documents/app_data/radium/Applet/packages/<appid>/<version>/
~/Library/Group Containers/5A4RE8SF68.com.tencent.xinWeChat/Library/Caches/xinWeChat/<hash>/WeApp/LocalCache/release/<appid>/<n>.wxapkg  # <3.8.0
```
- <3.8.0：前 1024B AES-ECB + 尾部 `WAPkgEncryptedTagForMac`，需 Frida 提 key。
- 3.8.0+：多数明文；4.x 可能明文或 V1MMWX，看文件头。

**Android**
```
/data/data/com.tencent.mm/MicroMsg/<userhash>/appbrand/pkg/*.wxapkg
/data/data/com.tencent.mm/MicroMsg/appbrand/pkg/general/*.wxapkg
/data/user/999/com.tencent.mm/MicroMsg/<userhash>/appbrand/pkg/
```
- 需 root/root 模拟器；包名多为数字，不是 AppID；通常明文。
- Android 11+ 分区存储可能使 `/sdcard/Android/data` 不可访问，优先 `/data/data`。

**iOS**
```
/var/mobile/Containers/Data/Application/<UUID>/Library/WechatPrivate/<hash>/WeApp/LocalCache/release/<appid>/<n>.wxapkg
```
- 越狱 + OpenSSH/Filza；文件夹名即 AppID；通常明文。

**企业微信**
```
C:\Users\<user>\Documents\WXWork\<corp>\Applets\Applet\<version>\
```
版本差异大，先递归搜 `*.wxapkg` 再检测头。

**开发者工具**：不存在"打开任意小程序就有明文 wxapkg"的稳定路径；`WeappFileSystem` 是运行时文件系统，`WeappVendor` 是框架代码。

### 1.4 包类型识别

| 文件/形态 | 含义 |
|---|---|
| `__APP__.wxapkg` | 主包（3.x/4.x） |
| `__FULL__.wxapkg` | 整包（主+部分/全部分包，部分 3.x 有） |
| `__SUBCONTEXT__.wxapkg` | 子上下文包 |
| `_pages_<module>_.wxapkg` | 4.x 分包（按需下载） |
| `_subpackages_xxx_.wxapkg` / `pages_subpkg.wxapkg` | 分包其他命名 |
| `plugin.wxapkg` / `__PLUGINCODE__.wxapkg` | 插件包 |
| `__plugin__/...` | 主包内插件虚拟目录 |
| `workers.js` | Worker bundle |
| `game.js` / `game.json` | 小游戏 |
| `WA*` / `publicLib` | 基础库/框架 |

内容类型判断：
```
page-frame.html + common.app.js   -> APP_V4
page-frame.html                   -> APP_V1
common.app.js + app-wxss.js       -> APP_V3
common.app.js                     -> APP_SUBPACKAGE_V2
page-frame.js + app-wxss.js       -> APP_V2
page-frame.js                     -> APP_SUBPACKAGE_V1
game.js + app-config.json         -> GAME
plugin.json + appservice.js       -> APP_PLUGIN_V1
```

优先级：`__APP__` > `__FULL__` > `__SUBCONTEXT__` > 其他 > `__PLUGINCODE__`；按 `appid+version` 分组，用 `__APP__` + 同版本全部分包。

### 1.5 app-config.json 关键字段

- `entryPagePath`、`pages`、`page`（每页 window/usingComponents/component/renderer）、`global`（window/tabBar/networkTimeout）。
- `subPackages`/`subpackages`（root/pages/independent）。
- `plugins`（provider/version/export/subpackage）。
- `workers`、`lazyCodeLoading`、`componentFramework`（exparser/glass-easel）、`renderer`（webview/skyline）。
- `permission`、`requiredPrivateInfos`（隐私合规重点）。
- `tabBar.iconData` 可能是 base64，还原需落图片。

### 1.6 新趋势

- **`__wxCodeSpace__` / glass-easel / Skyline**：`batchAddCompiledTemplate` 把 WXML 编译成函数链，只认 `$gwx` 的工具会失败/占位。检测到应标记 `partial`，用新工具或动态调试。
- **代码加固**：官方 `devtool-code-obfuscation`（字符串/属性/调用混淆、反调试）；商业 JSVMP/WASM/SM4。加固包仍可解包，但核心逻辑需动态 Hook/LLM；不要承诺完整还原。
- **WASM**：`WXWebAssembly.instantiate`，`.wasm.br` 用 brotli 解压；wabt/Ghidra/wasmtime。
- **Source Map**：官方明确正式包不含；开发版/后台 `getDevSourceMap` 才可能有。包内出现 `.map` 是高价值发现。

### 2.2 KillWxapkg v2.4.1 实测

- Linux 无预编译，`go build` 可用（本次已实测 amd64/arm64 静态 ELF，11MB）。

## 3. 敏感信息与接口提取

### 3.1 敏感项

- 微信：AppSecret（32 hex）、AppID（`wx[0-9a-f]{16}`，公开）、mchid/mchkey、session_key/openid/unionid。
- 云开发：`env`、`callFunction name`、`collection`、`cloudPath`。
- 地图：腾讯地图 6 段 key、高德/百度 32 hex + 上下文。
- 监控：Bugly/MTA/Sentry DSN。
- 令牌：JWT、AES key/iv、CryptoJS。
- 云存储：阿里 `LTAI`、腾讯 `AKID`、AWS `AKIA`、GCP `AIza`、七牛 40 位、STS/uploadToken。
- 域名：非公开 TLD、IP、`.local/.internal/.corp`、test/dev/staging/pre/uat。
- Webhook：企微/钉钉/飞书/Slack。
- PII：手机号/身份证/银行卡/邮箱（脱敏）。

原则：正则+上下文+熵+去重；高置信（AppSecret/支付密钥/AKSK/私钥）、中低置信（AppID/env/地图 key）；报告只留脱敏值+file:line。

### 3.2 接口模式

```js
wx.request / wx.uploadFile / wx.downloadFile / wx.connectSocket
wx.cloud.callFunction / database().collection / uploadFile / downloadFile / getTempFileURL / deleteFile
wx.navigateToMiniProgram({appId,path,extraData})
requirePlugin('plugin://...')
uni.request / tt.request / my.request / swan.request
axios / fetch / $.ajax / new WebSocket
```

- 封装层（request.js/http.js/api.js）要识别 `request.get('/api')`、`request({url})`。
- 提取 `baseURL/apiHost/globalData.baseUrl/config.js` 常量，再与路径拼接。
- 动态拼接需 AST/常量传播/LLM。
- semgrep/ast-grep 规则示例见调研原文；wxmini-security-audit 的 `endpoint_extractor.py` 覆盖最全。

## 4. 工程化流水线

```
收集/上传（appid+version 分组，SHA-256）
  -> 头部检测（plain / V1MMWX / mac-legacy / unknown）
  -> 索引预校验（拒绝 ..、绝对路径、盘符、UNC、NUL、超长、符号链接）
  -> 解密（V1MMWX / mac）
  -> 安全解包（自研 parser + wedecode/unveilr/killwxapkg）
  -> 质量门禁（app.json/pages/WXML 非空率/占位符/JS 语法/分包完整性/新模板标记）
  -> 静态分析（gitleaks + semgrep/ast-grep + endpoint extractor + OSV）
  -> 可选去混淆（沙箱）
  -> 报告（JSON/SARIF/Markdown，证据 file:line，密钥脱敏）
```

**质量门禁指标**：
- `app.json` 可解析、`pages` 非空、`entryPagePath` 在 pages。
- 每页至少一个非空 `.wxml`/`.js`（允许合法缺失）。
- WXML 非空率、占位符比例（`Generated by @unveilr`、空 `<block wx:if>`）。
- JS `node --check`/Babel parse。
- 分包/组件文件齐全。
- 检测 `batchAddCompiledTemplate`/`__wxCodeSpace__` → `partial`。

**manifest.json**：appid/version/source/packages(sha256/enc)/tool/status/warnings/wxml_nonempty_ratio。

**路径安全**：解包前校验 name；解析后 `realpath` 必须在输出根下；拒绝重复/大小写冲突；限制文件数 100k、单名 1KB、单文件 128MB、总量 1GB；沙箱非 root/无网络/cap-drop/内存/CPU/PID/超时。

**编码**：UTF-8（LANG/PYTHONUTF8），Windows chcp 65001；保留原始名到 `name_map.json`。

**大包**：整包读内存，先 `--unpack-only`/`-fast` 原始提取，再解析；并发 2-4。

## 7. 已知坑（精选）

1. KillWxapkg `-id` 必填，不传 exit 0。
2. `-in` 目录不递归，必须版本目录。
3. 包内路径穿越（实测）。
