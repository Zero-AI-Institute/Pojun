# 微信小程序渗透方法论调研（2026-11-23）

> 纯技术调研，用于构建 mini-program skill 的 references 知识库。不含授权/约束类内容（平台与模型侧已统一处理）。

---

## 0. 结论摘要

1. 小程序漏洞主体不是内存破坏或传统 Web 注入，而是 **API 鉴权缺失、水平/垂直越权、业务逻辑、前端信任、云开发配置错误、硬编码密钥**。
2. 三类独有攻击面必须单列：
   - **微信登录与开放数据**：`wx.login → code → code2Session → openid/session_key/unionid`，`getPhoneNumber` 的 code/encryptedData 流程；`session_key` 泄露可直接导致任意手机号登录。
   - **云开发（CloudBase）**：`wx.cloud.callFunction`、云数据库安全规则、云存储规则、云函数 HTTP API、环境共享、未登录模式。
   - **微信开放能力**：小程序码/URL Scheme/URL Link、订阅消息、客服消息、微信支付、发货信息管理、内容安全、分享/朋友圈、跨小程序跳转。
3. 固定作业链路：信息收集 → 取包 → 解密/解包 → 静态审计 → 抓包 → 登录态与接口测绘 → 接口测试 → 最小化验证 → 证据固定 → 报告 → 复测。
4. 报告与 Web 漏洞最大差异：目标用 **AppID + 页面路径 + 云环境 ID + 请求/响应** 定位；必须 A/B 双账号对照；必须记录微信版本/基础库版本。
5. 事实标准组合：微信官方《安全指引》《常见风险及处理建议》+《微信小程序安全需求基线》+ 腾讯 WeTest/MPSS 检测项 + OWASP MASVS/MASTG + OWASP API Top 10。

## 3. 抓包方案对比与排障

| 方案 | 适用场景 | 优点 | 缺点/限制 | 关键配置 |
|---|---|---|---|---|
| PC 微信 + Proxifier + Burp/Yakit | Windows/macOS 桌面小程序 | 最稳；可抓小程序+内置浏览器；不依赖 root | 需按进程转发；微信版本更新可能改进程名 | 进程：`WeChat.exe;WeChatAppEx.exe;WeChatPlayer.exe;WechatBrowser.exe;WeChatAppEx*.exe`；勾选 `Use target hostname in proxy request if available` |
| PC 微信 + Fiddler + Burp 二级代理 | Proxifier 不可用 | Fiddler 系统代理，上游 Burp | 需装 Fiddler 根证书到受信任根；重启微信 | Fiddler 导出证书；上游代理指向 Burp |
| 安卓模拟器 + Burp/Charles | 需要 root/系统证书/旧版微信 | 可装系统证书；可改包/重打包 | 安卓 7+ 用户证书不信任；新版微信只信任自带证书列表 | 夜神/雷电 Android 5/6；或 root + Magisk 系统证书；或 Postern/SOCKS |
| 安卓真机 + Postern/SOCKS + Burp | 真机行为、微信风控 | 接近真实环境 | 需 root 或 VPN 模式；证书问题 | Postern 配置 SOCKS5 指向 Burp；全局转发 |
| iOS + Burp/Charles | iOS 小程序 | 系统代理通常生效；证书信任简单 | iOS 15+ 需手动"证书信任设置"；部分 pinning | 安装描述文件后到"关于本机 > 证书信任设置"开启 |
| 透明代理/Clash TUN/mitmproxy | 小程序不走系统代理 | 不依赖应用代理设置 | 需网关/DNS/证书；排障复杂 | Clash TUN + 规则；mitmproxy `--mode transparent`；网关 NAT |
| r0capture/Frida/objection | SSL pinning、双向认证 | 可在 Java 层抓明文；绕过 pinning | 需 root/越狱；有封号风险 | `objection -g 包名 explore` → `android sslpinning disable`；r0capture |
| CDP/WMPF 调试 | 需要 F12、看路由、改 JS | 可动态调试、看 storage、执行 JS | 版本敏感、偏移变化、封号风险 | WeChatOpenDevTools-Python、WMPFDebugger、e0e1-wx |

**"小程序不走系统代理"原因树**（按排查顺序）：
1. PC 微信 3.4.5 之后小程序由 `WeChatAppEx.exe`/WMPF 运行时承载，使用自身网络栈，不读系统代理 → Proxifier/ProxyCap 按进程强制转发。
2. 安卓 7+ 不信任用户证书；微信 7.0+ 只信任自身配置的证书列表 → root+系统证书、Android 5/6 模拟器、Frida/JustTrustMe、r0capture。
3. 证书未安装/未信任/装错位置；Burp 监听 `127.0.0.1` 而非 `0.0.0.0`；防火墙；不同网段。
4. 代理软件冲突（Clash/Proxifier 循环检测）；DNS 污染；IPv6；QUIC/HTTP3。
5. 应用层 SSL pinning/双向认证 → Frida/objection/r0capture/客户端证书。
6. WebSocket/长连接、私有协议（微信 mmtls）不经过 Burp；通常不是业务接口。

**实操顺序**：先浏览器基线验证 → PC 微信重启 → 真实进程名 → 模拟器 Android 5/6 → 透明代理排除应用代理 → 最后查 pinning。

## 4. 登录态机制与越权测试

### 4.1 标准登录链路

```
小程序                          开发者服务器                      微信服务器
  | wx.login() -> code(5min,一次性) |                                |
  | ---- code --------------------> |                                |
  |                                | GET /sns/jscode2session        |
  |                                | appid+secret+js_code+grant_type|
  |                                | -----------------------------> |
  |                                | <---- openid, session_key, unionid
  |                                | 生成自定义 token（绑定 openid） |
  | <---- token ------------------- |                                |
  | 存 storage，后续请求带 token     |                                |
```

- `code` 5 分钟、一次性；`code2Session` 必须服务端调用。
- `session_key` 是开放数据 AES 密钥，**不得下发客户端**；泄露 + `encryptedData/iv` 可解密手机号等。
- `unionid` 用于同开放平台多应用打通；泄露可跨应用关联。
- 自定义登录态：随机 token 绑定 openid + 过期时间；不要把 openid/unionid 当 token；不要放 URL。

### 4.2 手机号快速验证

新流程（推荐）：
1. `<button open-type="getPhoneNumber">` 回调拿 `e.detail.code`（5 分钟、一次性）。
2. 服务端 `POST https://api.weixin.qq.com/wxa/business/getuserphonenumber?access_token=...`，body `{"code":"..."}`。
3. 返回 `phone_info.phoneNumber / purePhoneNumber / countryCode / watermark`。
4. 服务端校验 `watermark.appid` 后绑定。

旧流程：`encryptedData + iv + session_key`，AES-128-CBC/PKCS#7；`aeskey=Base64_Decode(session_key)`，`iv=Base64_Decode(iv)`，密文 `Base64_Decode(encryptedData)`；解密后校验 `watermark.appid`。

测试点：
- 请求/响应出现 `session_key`/`sessionKey`/`sk` → 高危，验证能否解密/重加密。
- 绑定接口是否只信客户端 `phoneNumber`；换成第二个手机号/他人手机号。
- `code` 是否可重放；服务端是否只消费一次；是否校验 appid。
- 是否前端解密、前端内置 AES key。
- 换绑手机号是否免旧验证。
- 是否用手机号作为登录/鉴权凭证。

### 4.3 未授权/越权测试矩阵（每敏感接口至少 8 态）

| # | 身份/凭证 | 目的 |
|---|---|---|
| 1 | 无 token | 未授权 |
| 2 | 空 token / `Bearer ` / `null` | 鉴权空值绕过 |
| 3 | 过期 token | 过期校验 |
| 4 | A 的 token + A 的资源 | 正常基线 |
| 5 | A 的 token + B 的资源 ID | 水平越权 |
| 6 | B 的 token + A 的资源 ID | 双向校验 |
| 7 | 普通用户 token + 管理员接口 | 垂直越权 |
| 8 | 伪造/篡改 token（alg none、弱密钥、kid/jku） | 令牌伪造 |
| 9 | 删 token 参数/改参数名/改方法/改 Content-Type | 鉴权绕过 |
| 10 | 重放旧请求/旧 code/旧签名 | 重放 |

补充：`userId/openid/unionid/member_id/uid/customerId/phone` 替换；`role/isAdmin/vip/level/status` 客户端可控位；`X-WX-OPENID`/`X-WX-UNIONID`/`X-Forwarded-For` 误用；token 在 URL/Referer/日志；退出失效；多端并发；GraphQL `node(id:)`/introspection；批量/导出接口 `pageSize`/`export`。

## 5. 云开发（CloudBase）安全

### 5.1 攻击面

1. **envId 泄露**：`env: "xxx"`；envId 非密钥但可定位环境。
2. **云函数名枚举**：`callFunction({name})` 全提取；函数名暴露业务（`adminDeleteUser`、`getAllOrders`）。
3. **云函数鉴权缺失**：默认规则 `{"*":{"invoke":"auth != null"}}` 只要求登录；函数内不校验角色/归属即未授权/越权。CloudBase 文档明确：安全规则只支持登录/匿名判断，细粒度权限必须在函数内实现。
4. **云函数 IDOR**：参数直接拼 `openid/userId/orderId`；可信身份是 `getWXContext().OPENID`。
5. **云函数注入/SSRF/RCE**：用户可控 URL → SSRF（`http://metadata.tencentyun.com/latest/meta-data/`、内网）；`child_process.exec`/`eval`/`new Function`/`fs.readFile` 拼接 → 命令执行/任意文件读写；NoSQL 注入（`$ne/$gt/$where`）。
6. **数据库规则**：
   - `read:true` → 所有登录用户可读全表；`write:true` → 可写全表。
   - `auth.openid != null` → 只校验登录，不校验归属。
   - 规则要求查询条件是规则子集；`doc.get()` 只带 `_id` 常不满足；须 `where({_id,_openid:'{openid}'})`。
   - `get()` 跨文档引用可遍历。
   - `aggregate/watch/count` 也要测规则约束。
7. **云存储规则**：`read:true` 任意下载 fileID；`write:true` 任意上传/覆盖；服务端/控制台始终全权限；fileID 可预测可枚举。
8. **HTTP API**：`tcb/invokecloudfunction` 需 access_token；AppSecret 泄露即可调用；云函数 HTTP 触发器可能公网。
9. **环境共享/多小程序**：A 用户可能访问 B 应用数据；测跨 appid 边界。
10. **未登录模式/单页模式**：`auth == null`；规则 `read:true` 时匿名可读。

### 5.2 测试步骤

1. 反编译 → 提取 `wx.cloud.init`/`env`/`callFunction name`/`collection(...)`/`uploadFile` 路径。
2. 自己账号走正常业务，记录每函数调用与参数。
3. 每函数参数最小化/置空/类型混淆/换 ID/加 openid；观察错误是否泄露函数名/集合名/堆栈。
4. 数据库：客户端 SDK 直查 `db.collection('x').get()`；全量 → `read:true`；再测 `where({_openid})`/`doc(id).get()`/`update/remove`/`count/aggregate/watch`。
5. 存储：`downloadFile({fileID})`；他人 fileID、可预测路径、任意上传、覆盖、删除。
6. 云函数内部：SSRF（collaborator 域名）、命令注入（无害 echo）、路径遍历、NoSQL 注入（`$ne`）。
7. 拿到 AppSecret/AK/SK：只读最小验证，不批量、不影响线上。
8. 证据：envId、函数名、集合名、请求/响应、A/B 数据对比、规则配置截图。

## 7. 小程序漏洞类型全清单（43 类摘要）

### 认证与授权
1. 未授权访问：无鉴权/可绕过；删/空 token、改方法/Content-Type；证据=无凭证返回敏感数据；误报=401/403、公开数据。
2. 水平越权 IDOR：对象 ID 可替换、只按 ID 查询；A/B 双账号、±1、UUID、批量/导出/GraphQL；≤5 条；误报=403、同用户、不可枚举。
3. 垂直越权：角色校验缺失/管理接口暴露；普通账号访问管理路由、改 role/isAdmin；误报=本就公开。
4. 任意用户登录/账号接管：session_key 泄露、手机号只信客户端、验证码绕过、换绑免旧验证；解密改手机号重加密；证据=用 A 会话登录 B。
5. 任意密码重置：验证码回显/爆破/可删、响应改 code、用户枚举、Host 注入；误报=前端提示成功后端未改。
6. JWT：alg none、弱 HMAC、kid/jku/x5u、不校验 exp/aud/iss、token 在 URL；误报=仅前端 decode。
7. 会话管理：退出不失效、token 可预测、会话固定、多端不踢、无过期。
8. 短信/邮件轰炸：无图形验证/频控/人机；只测自己手机号 ≤50；测删参数、改 scene/mobile。
9. 用户枚举：登录/注册/找回响应差异、时序差异；误报=统一文案、WAF 干扰。

### 数据与信息
10. 硬编码密钥：AppSecret/AKSK/商户密钥/短信 key/地图 key/JWT secret/AES key/私钥；熵检测；最小只读验证。
11. 信息泄露：sourceMap、vConsole、`wx.setEnableDebug`、错误堆栈、Swagger、`.git`、测试环境。
12. 本地存储明文：token/手机号/身份证/银行卡；开发者工具/真机查看。
13. 日志泄露：console.log token/PII、实时日志上报。
14. 爬虫遍历：自增 ID、无频控、无登录；连续 5 个 ID 验证。
15. 文件下载 IDOR：fileId/path 可替换、无归属校验、路径遍历。

### 业务逻辑
16. 支付金额/数量篡改：客户端价格/数量、负数/小数/0、优惠券前端算；0.01 元/沙箱。
17. 支付回调伪造/重放：未验签、只验 return_code、不校验金额/商户号/订单号、无幂等。
18. 退款逻辑：退款>实付、多次累计超额、退款给他人、无权限。
19. 优惠券/积分/会员：并发领取、负数、叠加、无限领、IDOR、客户端判 VIP。
20. 条件竞争：领取/兑换/抽奖/提现无锁；并发 5-10。
21. 步骤跳过/状态篡改：多步流程跳步、状态由客户端传。
22. 响应包篡改/前端绕过：前端按 code/status/isAdmin 判断、后端未复验；必须证明后端接受后续请求，否则仅前端变化不算。

### 注入与执行
23. SQL 注入：拼接、order by/like/in；只读证明。
24. NoSQL 注入：对象直传、`$ne/$gt/$where/$regex`、类型混淆。
25. 命令注入：`exec/system/popen` 拼接；无害 echo 证明。
26. SSRF：图片代理、URL 预览、webhook、云函数 axios；collaborator/内网/元数据。
27. 文件上传：类型/后缀/MIME/magic 缺失、云存储公开写、SVG/HTML、路径穿越、覆盖。
28. 路径遍历：`../`、编码、双写；只读自己测试文件。
29. XSS（web-view/H5）：反射/存储、JSSDK 调用、postMessage。
30. 开放重定向：redirect_url/returnUrl 未白名单、`//evil.com`、编码绕过。
31. CSRF/CMRF：分享路径/小程序码携带参数 + 已登录态自动请求；双账号、只读/可回滚。

### 云开发/开放能力
32. 云函数未授权/越权：`invoke:true`、只校验登录、函数内无角色/归属。
33. 云数据库规则错误：`read/write:true`、只校验登录、doc 查询绕过、get() 遍历。
34. 云存储未授权：read/write true、fileID 枚举、临时 URL 长期有效。
35. 小程序码/URL Link 参数注入：scene/page/query 拼 SQL/URL/模板、check_path:false、env_version 可控。
36. 订阅/客服消息滥用：touser/page 可控、无频控、模板未转义。
37. 支付回调伪造：未验签/可绕过、金额/商户号不校验、无幂等。

### 客户端与供应链
38. 签名算法可逆/绕过：密钥硬编码、签名不覆盖全参数、时间戳不校验、可删除、MD5/HMAC 弱；删 sign、改 body 不重算、重放。
39. 插件/第三方 SDK 供应链：plugin.json、requirePlugin、usingComponents、SDK 版本、CVE、权限。
40. 调试模式/sourceMap：生产包 debug、vConsole、map 公开。
41. 隐私合规：未同意先收集、过度收集、明文 PII、无注销/撤回、SDK 未披露。
42. 传输安全：HTTP、字段明文、Base64 当加密、PII 放 URL/Header。
43. 接口签名逆向：减法确定 sign 参数、反编译定位 HMAC/MD5、Python 复现、重放/篡改验证。

## 8. web-view / 插件 / Worker / 跨小程序跳转

**web-view**
- 只能加载后台配置的业务域名；HTTPS、不能 IP/localhost。
- 风险：`src` 用户可控 → 开放重定向/钓鱼；H5 XSS → 调 JSSDK（`wx.miniProgram.navigateTo`、`postMessage`、`getEnv`）；`postMessage` 未校验 → token/userId/redirect 被信任；Cookie/localStorage 共享与退出清理。
- 测试：自己的 H5/测试域名；构造 src；H5 内 console.log 证明执行；检查 bindmessage 处理。

**插件**
- 数据隔离，除非主动传递。
- 风险：插件方被攻破/恶意更新；收集用户信息；API 权限过大；版本未锁定；功能页（支付/收货地址/发票）参数篡改。
- 测试：plugin.json、requirePlugin、AppID/版本；页面入参；回传敏感数据；CVE。

**Worker**
- 独立线程，不能操作 UI；仍沙箱内；postMessage。
- 风险：CPU/内存滥用、算法/密钥放 worker（仍可逆）、脚本篡改（重打包）。SRC 价值低。

**跨小程序跳转**
- `navigateToMiniProgram({appId,path,extraData,envVersion})`、`openEmbeddedMiniProgram`、`navigateBackMiniProgram`。
- 风险：appId/path 用户可控 → 钓鱼/测试版；目标页信任 extraData；`envVersion: develop/trial` 打开未发布版本。
- 测试：改 appId 为自建测试小程序；改 path；注入 extraData。

**CMRF（跨小程序请求伪造）**
- 页面 `onLoad(options)` 接收参数 + 本地已登录 token 自动请求；构造分享路径/小程序码让受害者打开完成请求。
- 测试：双账号；构造 `path?action=...&id=...`；只读/可回滚；证据=受害者状态变化+请求日志。

## 10. 检查清单

### 信息收集
- 小程序名称/AppID/主体/开发者/客服/版本/更新时间/基础库版本。
- "更多资料"的服务及数据网址（request/upload/download/socket 域名白名单）。
- 关联公众号/视频号/APP/网站/备案/ICP/商标/软著。
- 小程序码/URL Link/Short Link/URL Scheme；分享卡片路径。
- 主包/分包/独立分包/插件；`app.json` 路由全集；`sitemap.json`。
- 云开发 envId、云函数名、集合名、存储路径。
- 接口域名/子域/C 段/端口/指纹/WAF/CDN/测试环境（dev/test/uat/pre）。
- GitHub/Gitee 泄露、sourceMap、`.git`、Swagger、错误页、调试页。
- 隐私政策、第三方 SDK 清单、收集字段、权限申请。
- 企业信息：天眼查/企查查、子公司、邮箱、员工、供应链。
- 历史版本：第三方小程序商店、抓包缓存、旧版分包。
- 业务模式：电商/金融/医疗/教育/政务，锁定高价值接口。

### 接口测试
- 认证：无/空/过期/他人 token、JWT 篡改、alg none、弱密钥、kid/jku。
- 授权：水平/垂直/跨租户；userId/openid/unionid/member_id/orderId/addressId 替换。
- 方法/Content-Type：GET↔POST、JSON↔form、参数污染（`id=1&id=2`）。
- 参数：空/null/0/负数/小数/超大/数组/对象/Unicode/截断/重复。
- 注入：SQLi、NoSQLi、命令、SSTI、SSRF、XXE、反序列化、Log4j/SpEL/OGNL。
- 上传：后缀/MIME/magic/SVG/HTML/zip/路径穿越/覆盖/大小/云 fileID。
- 下载：fileId/path/url 替换、路径遍历、签名 URL 过期、批量导出。
- 支付：金额/数量/币种/优惠券/订单归属/prepay_id/回调/退款/发货。
- 消息：短信/邮件频控、验证码复用/回显/爆破、用户枚举。
- 业务：步骤跳过、状态篡改、响应篡改、并发、库存、积分、抽奖、会员。
- 云开发：函数名/鉴权/DB 规则/存储规则/HTTP API/环境共享。
- 开放能力：小程序码/URL Link 参数、订阅 touser/page、客服消息、跳转 appId/path。
- 隐私：PII 明文、未同意先收集、过度收集、本地存储、日志。

### 云开发专项
- envId 泄露；测试/生产是否区分。
- callFunction 函数名全集；每函数是否只校验登录。
- 安全规则 `*` 是否 `invoke:true`；是否排除匿名；函数级例外。
- 函数内部是否用 `getWXContext().OPENID` 而非入参 openid；角色/归属校验。
- 输入：SQL/NoSQL/命令/SSRF/路径遍历/eval/require(userInput)。
- 集合清单；每集合 read/write/create/update/delete 规则。
- 是否 `read:true`/`write:true`；是否只校验 `auth != null`；`doc._openid == auth.openid` 但查询未带 `_openid`。
- `doc.get/update/remove`；`where` 批量；`aggregate/watch/count` 绕过。
- `get()` 是否可遍历；`{openid}` 变量正确使用。
- 云存储 read/write；fileID 枚举；临时 URL 有效期；上传类型/大小；覆盖/删除。
- HTTP API access_token 来源；AppSecret 泄露；HTTP 触发器公网。
- 环境共享跨小程序；未登录模式 `auth == null`。
- 云函数日志/环境变量泄露密钥/内网地址/连接串。

### 支付专项
- 下单价格来自服务端 DB；商品/数量/价格/优惠券一致。
- 金额单位（分/元）、负数/0/小数/超大/币种。
- 订单归属 openid；不能支付他人订单；不能改 out_trade_no。
- prepay_id 绑定 appid/mchid/openid；requestPayment 签名正确。
- 回调：验签（Wechatpay-Signature+平台证书/公钥）、时间窗口、Wechatpay-Serial、APIv3 密钥解密、mchid/appid/out_trade_no/amount.total/payer.openid 校验、幂等。
- 不接受 return_code=SUCCESS 作为唯一依据；不接受客户端"支付成功"。
- 退款：权限、金额≤实付、累计≤实付、原路退回、回调验签、状态机、并发。
- 发货：uploadShippingInfo 订单归属、物流单号、虚拟发货、notifyConfirmReceive。
- 对账：日账单、异常订单、重复支付、掉单。
- 沙箱/测试商户/0.01 元；不真实发货。

### 隐私合规
- 首次运行隐私弹窗；非默认勾选；拒绝后基本功能可用。
- 收集前告知目的/方式/范围/期限；敏感信息单独同意。
- 实际抓包收集项与隐私政策/SDK 清单一致。
- 权限：位置/相机/麦克风/相册/剪贴板/通讯录/设备信息；最小必要。
- 传输 HTTPS；PII 不明文在 URL/Header/Body；字段级加密（AES-GCM/ChaCha20-Poly1305 带 iv/tag）；签名/HMAC 抗重放。
- 存储：本地不存明文 token/PII；服务端加密/脱敏；保留期限。
- 用户权利：查询/更正/删除/撤回/注销/投诉。
- 第三方 SDK：清单/目的/共享字段/单独同意/匿名化。
- 未成年人/敏感个人信息/出境。

## 11. 自动化审计

**流水线**：
```
采集（主包+全部分包）→ 解包/反编译 → 文件清单与完整性校验
→ 静态提取（路由/接口/密钥/云环境/签名函数/web-view/插件）
→ AST/污点分析 → LLM 语义审计（分片、证据优先）
→ 动态 auth matrix（4 态×角色）→ 人工复核 → 证据与报告
```

**静态提取规则（示例）**：
```python
PATTERNS = {
  "url": r"https?://[^\s\"'<>]+",
  "api_path": r"[\"'](/[a-zA-Z0-9_\-/{}.:]+)[\"']",
  "wx_request": r"wx\.request\s*\(\s*\{[^}]*url\s*:\s*[\"']([^\"']+)",
  "cloud_fn": r"wx\.cloud\.callFunction\s*\(\s*\{[^}]*name\s*:\s*[\"']([^\"']+)",
  "cloud_env": r"env\s*:\s*[\"']([a-zA-Z0-9\-]+)[\"']",
  "secret": r"(?i)(appsecret|accesskey|secretkey|api[_-]?key|mch[_-]?key|aes[_-]?key|private[_-]?key)\s*[:=]\s*[\"'][^\"']{8,}",
  "jwt": r"eyJ[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+\.[A-Za-z0-9_\-]+",
  "sign": r"(?i)(sign|signature|hmac|md5|sha1|sha256)\s*[:=]",
}
```
- 密钥加熵检测（Shannon）、gitleaks/trufflehog 规则、上下文判断。
- 接口提取处理字符串拼接、模板字符串、常量折叠；纯正则有漏报。

**AST/污点**：
- `@babel/parser` + `@babel/traverse`（或 acorn/esprima）解析 `app-service.js`。
- Source：`options.query`、`event.detail`、`wx.getStorageSync`、`wx.getUserProfile`、`this.data`。
- Sink：`wx.request`、`wx.uploadFile`、`wx.cloud.callFunction`、`web-view src`、`wx.navigateTo`、`wx.setStorage`、`eval`。
- 关注：url 拼接、data 直接来自 source、sign 是否覆盖全参数、token 硬编码。

**LLM 分层**：
- 脚本全量扫保证规则覆盖；LLM 只做语义复核/误报过滤/上下文关联。
- 分片按文件/函数；每片输出 JSON：`{file,line,type,confidence,evidence,missing_evidence}`。
- 证据优先：无请求/响应/代码行号不算 confirmed；区分 hypothesis/confirmed/rejected/blocked。
- 不要把含 PII/密钥代码发给外部 LLM；优先本地模型或脱敏。

**动态 auth matrix**：
- 从 app.json 提取路由，CDP/自动化逐页访问，记录所有请求。
- 每请求 4 态：无凭证、真 ID+空 token、真 ID+假 token、随机 ID。
- 响应分类：认证缺失、水平越权、垂直越权、跨租户、404、公开资源。
- 工具：Burp AuthMatrix/Authz、mitmproxy 脚本、Playwright/CDP。

## 12. 报告写法

**结构**：
1. 基本信息：小程序名称、AppID、主体、版本、基础库、微信版本、设备/系统、入口路径/小程序码、云环境 ID。
2. 漏洞概述：类型、CWE/OWASP 映射、等级、影响范围。
3. 复现环境与账号：账号 A/B、时间、IP、授权依据、测试数据量。
4. 复现步骤：编号步骤、页面路径、请求/响应原文、A/B 对比、关键参数高亮。
5. 影响与证据：可读字段、记录数（≤5）、业务影响；截图/录屏；证据哈希。
6. 根因分析：前端信任、后端缺鉴权、云规则错误、签名/加密缺陷、支付状态机。
7. 修复建议：后端鉴权、云函数校验、DB/存储规则、服务端算价、密钥轮换、隐私整改。
8. 证据附件：Burp XML/项目、截图、录屏、请求 ID、时间戳。
9. 测试声明：仅授权范围、未批量、数据已删除、未影响业务。

**与 Web 报告差异**：
- 目标定位：AppID + 页面路径 + 云环境/函数/集合，不是 URL。
- 登录态：code→openid→token；写清账号、openid（脱敏）、token 获取方式。
- 请求可能被签名/加密；说明如何解密/重签。
- 云开发无传统 URL；写 envId、函数名、集合名、规则配置。
- 证据必须含小程序名称/页面路径截图或录屏。
- 记录版本/基础库/微信版本。
- 客户端-only "成功"不算；必须证明后端状态/数据变化。

**常见驳回原因**：
- 只改前端/响应，后端未接受；无实际数据。
- 读取公开信息/商品数据；无敏感性。
- 批量读取/拖库。
- 使用他人真实账号/手机号；证据不可用。
- 无法复现；缺请求/响应/页面路径。
- 与已知/重复漏洞重复。
- 测试了非授权资产/第三方。
- 支付漏洞仅理论推测/沙箱不生效。
