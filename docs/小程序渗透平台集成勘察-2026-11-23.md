## 七、目录/zip 上传缺口

### 现状可用

### 缺口（按严重度）
1. **无目录上传**：三处 file input 都无 `webkitdirectory`
2. **即使加目录上传，后端会拍平层级**：`chatupload.go:96` `filepath.Base`；需保留 `webkitRelativePath` 安全 join
3. **无 zip 自动解压**：可复用 `server/skill_zip.go` 的压缩探测/GBK/zip-slip 校验与 20MB 上限（`server/server_mgmt.go:1287`），需新 caps（条目数/解压总量/单文件）防 zip bomb
4. **staging 不迁移不清理**：建任务不搬 `drafts/<draftId>/uploads` 到 `tasks/<id>`，gc 空实现（`server.go:4557`）；历史任务描述绝对路径长期指向 drafts，数据目录迁移失效
5. **附件只对 task/session 计数**：chatUpload 不受 artifacts 配额约束
6. **上传包不能直接登记证据**：worker runDir=`tasks/<id>/i<N>`，save_evidence 拒绝 `../uploads`；必须先复制/解包到 runDir
7. **响应体只含单文件清单**：批量上传无「上传根目录」概念；目录上传会大量条目且同名不同子目录无法区分

## 一句话总结

上传通道、技能注入、工具目录、Playbook 种子、证据/报告链路都已存在且边界清晰；真正新增只有 4 处核心：**一个技能目录 + 一条可见性绑定 + 一个目录型扫描工具（或 js_audit dir 模式）+ 一个 Playbook 批次**。最大隐形坑是三处老库迁移语义：js_audit 的 required 不会自动放开、Playbook v1 flag 会让新条目对老库永久不可见、save_evidence 的 runDir 相对路径限制会挡住 uploads 里的包直接入证。
